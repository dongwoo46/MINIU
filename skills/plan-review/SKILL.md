# 기획 문서 검토

문서를 대신 다시 쓰지 않고 개발 재작업을 만드는 결함만 찾는다.

## 흐름

1. 대상 문서와 연결된 상위·하위 문서, 관련 코드를 함께 읽는다.
2. `node tools/docs.js check <파일...>`을 실행한다.
3. 기능 문서는 `node tools/docs.js trace <기능-slug>`, 상위기획은 `node tools/docs.js trace-plan <기획-slug>`로 연결 상태를 확인한다.
4. 문제·목표·MVP 범위가 서로 맞는지, 요구사항이 PRD에서 기능명세와 기술설계까지 이어지는지 본다.
5. 상태·실패·권한·데이터 경계와 구현 타당성 중 비어 있는 결정만 지적한다.
6. 발견마다 문서 위치, 영향, 필요한 결정 또는 수정 방향을 적는다.
7. 문제가 없으면 확인한 문서와 실행하지 못한 검사를 함께 보고한다.

## 경계

- 리뷰만 요청받았으면 문서를 수정하지 않는다.
- 표현 취향보다 범위, 추적성, 구현 가능성을 우선한다.
