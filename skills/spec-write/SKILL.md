# 기능명세 작성

PRD 요구사항을 빠짐없이 동작 규칙으로 바꾼다.

## 흐름

1. 대상 PRD 전체와 관련 코드·기존 문서를 읽는다.
2. `node tools/docs.js init spec <기능-slug> "<기능명>"`으로 초안을 만든다.
3. PRD의 모든 `R-n`을 기능 상세 제목에 그대로 연결한다.
4. 각 요구사항에 입력, 동작, 결과, 완료 조건을 적는다.
5. 빈 상태, 로딩, 오류, 재시도, 중복 실행, 권한 없음, 데이터 없음 중 해당 분기를 명시한다.
6. 기획 의도가 필요한 빈칸은 답을 만들지 않고 `미결정`에 질문으로 남긴다.
7. `node tools/docs.js check <파일>`과 `node tools/docs.js trace <기능-slug>`를 실행한다.

## 경계

- 필드명, 라이브러리, 엔드포인트 같은 구현 선택은 기술설계로 넘긴다.
- PRD 범위를 조용히 넓히지 않는다.
- 테스트케이스 문서는 만들지 않는다. 완료 조건만 명세에 둔다.
