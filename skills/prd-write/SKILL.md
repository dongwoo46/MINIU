# PRD 작성

결정된 내용만 짧게 기록해 바로 기능명세로 넘긴다.

## 흐름

1. 기존 코드와 `docs/features/`에서 같은 기능을 먼저 찾는다.
2. 독립된 PRD가 여러 개 필요하면 `planning-write`로 넘긴다.
3. 목표, 대상 사용자, 핵심 흐름, 이번 범위가 불명확하면 영향이 큰 질문부터 묻는다.
4. `node tools/docs.js init prd <기능-slug> "<기능명>"`으로 초안을 만든다. 같은 파일이 있으면 새로 만들지 않고 갱신한다.
5. `templates/prd.md` 구조를 유지하며 요구사항을 `R-1`부터 붙인다.
6. 각 요구사항에 사용자가 확인할 수 있는 완료 조건을 한 줄로 적는다.
7. 실패·빈 상태·권한·데이터 누락 중 기능에 실제로 해당하는 것만 포함한다.
8. 답이 없는 값은 추측하지 않고 `미결정`에 질문과 막히는 작업을 남긴다.
9. `node tools/docs.js check <파일>`을 통과시킨다.

## 경계

- 구현 방식, API, 스키마는 쓰지 않는다. 기술설계의 몫이다.
- 문서 분량보다 범위와 완료 조건의 명확성을 우선한다.
