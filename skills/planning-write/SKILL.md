# 상위기획 작성

여러 기능이 공유할 문제, 방향, MVP 경계를 먼저 정한다.

## 흐름

1. 기존 코드와 기획 문서를 읽어 이미 정한 방향과 제약을 찾는다.
2. 하나의 기능이면 상위기획을 만들지 않고 `prd-write`로 넘긴다.
3. `node tools/docs.js init planning <기획-slug> "<기획명>"`으로 초안을 만든다.
4. 관찰한 사실과 아직 검증하지 않은 가정을 구분해 문제와 목표를 적는다.
5. 선택한 방향, 기각한 대안, MVP 포함·제외 범위를 짧게 정리한다.
6. 파생 기능을 slug와 우선순위로 나누되 개별 요구사항은 각 PRD에 남긴다.
7. 결과를 바꾸는 미결정은 추측하지 않고 질문과 영향을 기록한다.
8. `node tools/docs.js check <파일>`과 `node tools/docs.js trace-plan <기획-slug>`를 실행한다.

## 경계

- 화면 분기, API, 스키마, 구현 순서는 각각 기능명세와 기술설계에서 정한다.
