# 개발 리뷰

변경분에서 실제 결함 가능성이 있는 항목만 보고한다.

## 흐름

1. `git status --short`와 관련 diff를 확인한다.
2. 해당 기능의 PRD, 기능명세, 기술설계를 읽는다.
3. 정확성, 상태·오류 처리, 권한·데이터 노출, 동시성, 성능, 기존 구조 재사용을 검토한다.
4. 프로젝트에 이미 있는 검사 명령을 실행한다. 없는 명령을 지어내지 않는다.
5. 발견마다 파일과 위치, 영향, 재현 조건, 권장 수정 방향을 적는다.
6. 문제가 없으면 확인한 범위와 실행하지 못한 검사를 함께 적는다.

## 경계

- 스타일 취향만으로 변경을 요구하지 않는다.
- 리뷰 요청만 받았으면 코드를 수정하지 않는다.
