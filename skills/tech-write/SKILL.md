# 기술설계 작성

명세를 재해석하지 않고 현재 코드에 맞는 구현 방법을 정한다.

## 흐름

1. PRD, 기능명세, 관련 코드를 읽고 재사용할 모듈과 제약을 찾는다.
2. 먼저 `가능`, `조건부`, `불가` 중 하나로 타당성을 판정하고 근거를 적는다.
3. `node tools/docs.js init tech <기능-slug> "<기능명>"`으로 초안을 만든다.
4. 구조와 책임, 데이터 변경, 인터페이스, 처리 흐름, 실패·복구를 필요한 만큼만 설계한다.
5. 구현 작업을 독립 검증 가능한 작은 순서로 나눈다.
6. 각 선택에는 근거와 기각한 대안이 있을 때만 기록한다.
7. 명세와 충돌하거나 제품 결정이 필요한 것은 `미결정`에 올린다.
8. `node tools/docs.js check <파일>`과 `node tools/docs.js trace <기능-slug>`를 실행한다.

## 경계

- 코드에서 확인할 수 있는 사실을 추측하지 않는다.
- 필요 없는 계층, 서비스, 추상화를 추가하지 않는다.
