# MINIU(미니유) 웹 MVP 기능명세

## 1. 기준과 범위

- 기반 PRD: `docs/features/miniu/prd.md` (용어·등급·정책은 PRD를 따른다).
- 포함: PRD §4의 R-1 ~ R-41 전체. 각 요구사항의 입력·트리거·동작·결과·완료 조건과 상태 전이, 분기·실패, 데이터·권한 규칙.
- 제외: 필드명·엔드포인트·스키마·라이브러리·모델 선택 등 구현 결정(기술설계 `tech.md`), 후속 페이즈 기능, 테스트케이스 문서, 아트 에셋 제작.
- 범위 제외(제품, PRD 재확인): 소셜 로그인, 사진 기반 외모 AI 분석, 실시간 대화, PWA, 별도 기념일 관리, 문자 스티커·스레드.

### 1.1 용어 정의

| 용어 | 정의 |
|---|---|
| 연인 | 사용자가 기록·미니유의 대상으로 삼는 상대. 문서 전체에서 "상대방" 대신 쓴다 |
| 미니유 | 사용자가 연인을 본떠 만든 캐릭터. 외형 5속성(헤어스타일·머리색·피부톤·얼굴형·표정) + 이름 |
| 커플 연결 | 두 계정을 1:1로 묶는 상태. 연결되어야 미니유 생성·기록·프로필·AI 채팅·문자·집 방문이 열린다 |
| 온보딩 | 회원가입 → 이메일 인증 → 커플 연결 링크 → 사전 질문 → 홈 첫 진입까지의 흐름 |
| 사전 질문 | 온보딩에서 연인의 사귄 날짜 + 5개 항목(좋아하는 것·싫어하는 것·성향·습관·가치관)을 묻는 단계. 모두 필수 |
| 기록 | 연인에 대해 알게 된 것을 적은 텍스트(≤150자) + 선택 날짜 |
| 사실 단위 | AI가 기록·사전 질문 응답·문자를 쪼갠 최소 정보 조각 |
| 프로필 카드 | 사실 단위를 5개 카테고리(좋아하는 것 / 싫어하는 것 / 가치관 / 습관 / 성향) 중 하나로 분류한 카드. 내용 + 출처(사전 질문 · 기록 · 문자) |
| 병합 | 의미가 같거나 포함 관계인 사실을 한 카드로 합치는 것. 항상 사용자 확인 후 |
| 말투 프로필 | 대화 캡처에서 AI가 요약한 연인 말투 6필드(분위기·어미·자주 쓰는 표현·이모지·답변 길이·반응 방식). 원문 미저장, AI 채팅 말투에만 사용 |
| 미니유 집 | 홈에서 이동하는 연인 미니유의 공간. 미니유 확인·꾸미기, 아이템 착용·해제, 애정표현 |
| 아이템 / 인벤토리 | 연인의 구체적 취향에서 파생된 착용·휴대형 아이템과 보관함(최대 10개) |
| 대표 문구 | 공유 이미지에 넣는 한 줄. AI 3개 제안 또는 사용자 직접 입력 |
| D-day | 연인과 사귀기 시작한 날. 사전 질문에서 입력받아 저장, 공유 이미지에 선택 표시 |
| 등급 | 요구사항 우선순위 — 필수(P0) / 메인(P1) / 서브(P2) |

### 1.3 AI 처리 파이프라인

MVP는 고정 체인으로 실행한다. LLM/모델 호출이 필요한 역할은 아래 5개.

| 역할 | 하는 일 | 관련 R | 실행 시점 |
|---|---|---|---|
| 분류기 | 원문(기록·사전 질문 응답·문자)을 사실 단위로 분리하고 5개 카테고리로 분류 | R-6, R-17, R-36 | 기록 저장·사전 질문 제출·문자 수신 후 비동기 |
| 병합 판정기 | 새 사실과 기존 같은 카테고리 카드의 의미 동일·포함 관계를 판단해 병합 후보 산출 | R-18 | 분류기 직후 |
| 말투 요약기 | 대화 캡처(멀티모달)에서 연인 메시지 중심 말투 6필드 요약 | R-26 | 캡처 업로드 시 |
| 채팅 응답기 | 프로필 카드 + 기록 + 문자 요약 + 말투 프로필로 답변 생성 | R-24, R-25 | AI 채팅 전송 시 |
| 대표 문구 생성기 | 프로필 카드 기반 대표 문구 3개 생성 | R-40 | 공유 이미지 화면 진입 시 |

- 아이템 제안(R-37)은 규칙 집계(빈도·형태 조건) + 취향 키워드 → 사물 매핑 테이블로 처리하고, 필요 시에만 문구 다듬기에 LLM을 쓴다.
- 병합은 자동 확정하지 않는다. 병합 판정기의 후보는 항상 사용자 확인(R-18)을 거친다.
- 분류·병합·말투·대표 문구 생성 실패는 원문 저장이나 다른 기능을 막지 않는다(R-19, §4).

### 1.4 공통 정책

- **커플 연결 게이팅**: 연결 전 허용 = 회원가입·이메일 인증·커플 연결 링크(SCR-04)·사전 질문(SCR-05)·홈 조회. 연결 후 허용 = 미니유 생성·수정, 기록, 프로필, AI 채팅, 문자, 집 방문·애정표현, 아이템, 공유 이미지. 잠긴 화면에 진입하면 "연인과 연결하기" 안내 + 링크·코드 재공유 수단으로 대체한다(R-10). 공유 이미지는 미니유가 있으면 가능하며, 미니유는 연결 후에만 생성되므로 실질적으로 연결 후 기능이다.
- **이미지 업로드 부분 실패**: 성공한 파일을 먼저 반영하고 "N개 이미지 업로드에 실패했습니다"를 알린다. 대화 캡처(R-26)·문자 첨부(R-33) 공통.
- **30일 유예**: 커플 연결 해제(R-11)와 계정 삭제(R-2)는 관련 데이터를 삭제 처리한 뒤 30일 유예를 두고 완전 삭제한다. 해제·삭제 전에 대상·유예·복구 불가를 안내한다.
- **민감 데이터**: 문자·기록·대화 캡처는 전송 구간 암호화. 대화 캡처 원본은 분석 직후 삭제하고 말투 요약만 저장한다(R-14).
- **기록 비공개 원칙**: 연인에 대한 기록·프로필 카드·사전 질문 응답·AI 채팅·말투 프로필은 **작성·생성한 본인만** 조회·수정·삭제한다. 커플로 연결되어도 연인에게 노출되지 않는다. 커플 연결이 여는 것은 문자(주고받음), 애정표현(내 공간에서 하고 상대에게 알림), 연인 미니유 상호작용이다.
- **시간 기준**: AI 채팅 일일 한도 초기화는 한국 시간(KST) 자정(R-27).
- **응답 시간 목표**: 기록 저장은 즉시(분류는 비동기), AI 채팅 첫 응답 5초 이내(초과 시 로딩 문구).
- **지속 상태**: 서버 저장. 브라우저 storage는 신뢰 저장소로 쓰지 않는다.

## 2. 기능 상세

### R-1 일반 회원가입

- 입력·트리거: SCR-01에서 이름·생년월일·이메일·비밀번호 입력, 필수 약관 동의 후 "가입".
- 동작: 형식 검증(비밀번호 8자 이상 16자 이하 + 숫자 + 특수문자 포함, 이메일 형식, 생년월일 유효, 약관 동의 체크) → 이메일 중복 확인 → 미인증 계정 생성 → 인증 메일 발송 → SCR-02로 이동.
- 결과: 미인증 계정과 인증 대기 상태가 생성된다.
- 완료 조건: 규칙 위반은 필드별 오류로 표시하고 가입을 막는다. 이미 가입된 이메일은 안내와 함께 차단된다. 가입 직후 SCR-02가 뜬다.

### R-2 로그인·로그아웃·세션

- 입력·트리거: SCR-03 이메일·비밀번호 제출 / SCR-18 로그아웃 / SCR-18 계정 삭제.
- 동작: 자격 확인 → 이메일 인증 완료면 온보딩 진행 위치(미완) 또는 홈으로, 미인증이면 SCR-02로. 세션은 httpOnly 쿠키로 유지. 로그아웃 시 세션 파기. 계정 삭제는 즉시 로그아웃 + 30일 유예 후 완전 삭제(유예 중 재로그인 시 취소).
- 결과: 인증 세션이 유지되고 재접속 시 같은 계정의 온보딩·미니유·커플·기록·카드가 이어진다.
- 완료 조건: 자격 불일치는 안내. 재접속 시 재로그인 없이 마지막 위치로 진입. 로그아웃 후 보호 경로 접근 시 SCR-03.

### R-3 상태 기반 라우팅 가드

- 입력·트리거: 모든 보호 화면 진입(레이아웃·페이지 각각).
- 동작: 미로그인 → SCR-03, 이메일 미인증 → SCR-02, 온보딩 미완 → 해당 단계(SCR-04/05), 커플 연결됐고 미니유 없음 → SCR-06에서 SCR-07 유도, 정상 → 요청 화면.
- 결과: 사용자는 항상 자기 진행 단계에 맞는 화면을 본다.
- 완료 조건: URL 직접 진입으로 단계를 건너뛸 수 없다.

### R-4 웹 셸과 하단 탭

- 입력·트리거: 로그인 + 온보딩 완료 후 앱 셸 렌더.
- 동작: 하단 고정 탭 4개(홈 / 기록 / 프로필 / 문자). 모바일 뷰 기준 반응형 — 최소 지원 폭 320px, 기준 폭 375px, 콘텐츠 최대 폭 460px(초과 화면은 460px 고정 + 중앙 정렬 + 배경 여백). 문자 탭에 안 읽은 문자 수 뱃지. 커플 미연결 시 잠긴 탭 진입 → 연결 안내.
- 결과: 어느 탭에서도 동일 셸·내비게이션.
- 완료 조건: 320px에서 가로 스크롤·요소 잘림 없음. 460px 초과 화면에서 콘텐츠 폭이 460px로 유지된다.

### R-5 커플 연결 링크·코드 생성

- 입력·트리거: 회원가입 직후 SCR-04 진입 / 이후 SCR-18·SCR-06 배너에서 재발급.
- 동작: 일회성 코드 + 초대 링크(`/connect?code=`) 생성. "이메일로 보내기" 선택 시 회원가입 때 인증한 이메일을 이용해 발송. 받은 링크·코드 입력란 제공. "건너뛰기"로 SCR-05로 진행.
- 결과: 코드가 발급(대기) 상태가 되고 공유 수단이 생긴다.
- 완료 조건: 연결이 성사되지 않아도 온보딩을 계속할 수 있다. 코드 만료 기간 경과 시 만료 표시 + 재발급 제공. 코드는 설정·홈 안내에서 다시 확인할 수 있다.
- 미결정: 초대 코드 이메일 공유의 발송 주체·수신자 지정 방식(§6).

### R-6 사전 질문

- 입력·트리거: 온보딩에서 SCR-05 진입.
- 동작: 사귄 날짜(타임피커)와 5개 질문(연인이 좋아하는 것 / 싫어하는 것 / 평소 성향 / 자주 하는 습관 / 가장 중요하게 생각하는 가치)에 답한다. 각 질문은 예시 문구를 보여주고 답변은 여러 개 입력 가능. 제출 시 분류기가 각 답을 사실 단위로 분리해 해당 카테고리 카드로 저장(출처 = 사전 질문), 사귄 날짜는 D-day로 저장.
- 결과: 초기 프로필 카드 세트와 D-day 값이 만들어진다.
- 완료 조건: 한 항목이라도 비어 있으면 제출이 막힌다. 첫 연결과 재연결에서 동일하게 동작한다. 제출 후 SCR-06으로 이동한다.

### R-7 홈 첫 진입

- 입력·트리거: 온보딩 완료 후 SCR-06 진입.
- 동작: 미니유가 없으면 미니유 자리에 물음표 + 안내를 표시. 커플 연결됨 → 물음표 탭 시 SCR-07. 미연결 → 물음표 탭 시 "연인과 연결하기" 안내(생성 불가) + 홈 상단 연결 배너(링크·코드 재공유).
- 결과: 사용자는 다음 할 일(연결 또는 미니유 생성)을 안다.
- 완료 조건: 미연결 상태에서는 미니유 생성 화면(SCR-07)에 진입되지 않는다.

### R-8 미니유 생성

- 입력·트리거: 커플 연결 상태에서 SCR-06 물음표 → SCR-07.
- 동작: 기본 프리셋 선택 → 헤어스타일·머리색·피부톤·얼굴형·표정·이름 설정 → 저장 → SCR-06에 연인 미니유 표시. 미연결 진입 시 생성 화면 대신 연결 안내.
- 결과: 미니유가 생성되어 홈·집·채팅·공유 이미지에서 렌더된다.
- 완료 조건: 이름은 필수, 외형 각 속성은 기본값이 있다. 저장 후 홈에 즉시 반영. 미연결 시 생성 불가. 생성 후에도 SCR-08에서 수정 가능(R-30).

### R-9 커플 연결 수락

- 입력·트리거: 연인이 코드 입력 또는 초대 링크 접속(로그인 상태).
- 동작: 코드 검증 — 본인 코드 / 사용·만료된 코드 / 이미 다른 상대와 연결된 계정은 각각 안내와 함께 차단. 유효하면 두 계정을 커플로 연결(1:1), 코드 사용 처리, 양쪽 잠긴 기능 활성화, 양쪽에 연결 완료 알림.
- 결과: 커플 상태가 "연결됨"이 된다. 온보딩 중 어느 시점에 수락되어도 즉시 반영된다.
- 완료 조건: 금지 케이스 3종 각각 문구가 다르다. 연결 즉시 홈·탭 잠금이 풀린다.

### R-10 연결 전 이용 범위

- 입력·트리거: 커플 미연결 사용자의 화면 진입.
- 동작: 허용 = 회원가입·이메일 인증·커플 연결 링크(SCR-04)·사전 질문(SCR-05)·홈 조회. 차단 = 미니유 생성/수정, 기록, 프로필, AI 채팅, 문자, 집 방문 → 진입 시 "연인과 연결하기" 안내 + 링크·코드 재공유. 그 외 요소는 잠금 표시.
- 결과: 연결 전에는 개인 온보딩만 가능하다.
- 완료 조건: 잠긴 화면에 URL로 직접 진입해도 안내로 대체된다.

### R-11 커플 연결 해제

- 입력·트리거: SCR-18에서 "연인 연결 해제" → 확인 화면.
- 동작: 확인 화면에 삭제 대상(문자·기록·프로필 카드·말투 프로필·관계 기반 아이템 제안 + 각자의 연인 미니유·사전 질문 원본 응답), 30일 유예 후 완전 삭제, 복구 불가를 명시 → 확정 시 해당 데이터를 삭제 처리(유예), 대기 중 초대 코드 만료, 양쪽 홈이 온보딩 재시작 상태로 전환.
- 결과: 관계 데이터가 유예 삭제 대상이 된다. 재연결 시 이전 데이터는 복구되지 않고, 온보딩(사전 질문 포함)을 다시 진행해 R-6과 동일하게 카드가 재생성된다.
- 완료 조건: 확인 없이 해제되지 않는다. 유예·삭제 대상·복구 불가가 해제 전에 안내된다.
- 미결정: 30일 유예 중 재연결로 삭제를 취소할 수 있는지(§6).

### R-12 로딩·빈·실패 상태

- 입력·트리거: 모든 화면의 로딩·빈 데이터·요청 실패·네트워크 끊김.
- 동작: 로딩은 상태 문구, 빈 데이터는 안내 + 다음 행동 유도, 요청 실패는 재시도 버튼 + 입력 로컬 보존, 네트워크 끊김은 자동 재시도 1회 후 수동 재시도.
- 결과: 무엇이 실패했고 무엇을 하면 되는지 항상 보이며 입력이 유실되지 않는다.
- 완료 조건: 어느 흐름에서도 빈 화면·무한 로딩·강제 종료가 없다. AI 채팅 응답 생성 실패는 사용 횟수를 차감하지 않는다.

### R-13 이벤트 로깅

- 입력·트리거: 핵심 사용자 행동 시점.
- 동작: 회원가입, 이메일 인증 완료, 사전 질문 완료, 미니유 생성 완료, 커플 연결 완료, 첫 기록 작성, 주간 기록·문자 수, 집 방문·애정표현 횟수, AI 채팅 사용·제한 도달, 아이템 제안 승인, 공유 이미지 저장, 7일·30일 재방문을 이벤트로 기록하고 사용자·커플 식별자로 연결.
- 결과: PRD §8 성공 지표를 산출할 수 있다.
- 완료 조건: 각 지표에 필요한 이벤트가 최소 1종씩 존재한다.

### R-14 민감 데이터 보호

- 입력·트리거: 문자·기록·대화 캡처 전송·저장, 계정 삭제, 커플 연결 해제.
- 동작: 전송 구간 암호화. 대화 캡처 원본은 분석 완료 직후 삭제하고 말투 요약만 저장. 계정 삭제·연결 해제 시 관련 데이터를 유예 후 영구 삭제. 지속 상태는 서버 저장.
- 결과: 원문 노출 표면이 최소화된다.
- 완료 조건: 대화 캡처 원본이 분석 이후 어디에도 남지 않는다.
- 미결정: 저장 구간 암호화 수준·보관 기간의 법적 검토(§6).

### R-15 기록 작성

- 입력·트리거: SCR-11에서 내용(텍스트 ≤150자) + 선택 날짜 → 저장.
- 동작: 길이 검증 → 기록 저장(분석 상태 = 대기) → 즉시 완료 응답 → 분류기 비동기 실행(R-17).
- 결과: 기록 목록에 즉시 표시되고 분석 진행 상태가 보인다.
- 완료 조건: 151자 이상 입력은 차단된다. 저장이 AI 분석 완료를 기다리지 않는다.

### R-16 기록 조회·삭제

- 입력·트리거: SCR-11 목록 조회 / 항목 삭제 → 확인.
- 동작: 본인이 작성한 기록만 최신순으로 표시(연인의 기록은 조회 대상이 아니다). 기록을 삭제하면 그 기록이 출처인 프로필 카드도 함께 삭제한다.
- 결과: 기록과 그 기록에서 나온 프로필 카드가 사라진다.
- 완료 조건: 삭제 확인 후 목록·프로필에서 즉시 제거된다. 되돌리기 없음이 사전 고지된다.

### R-17 사실 단위 분리와 자동 분류

- 입력·트리거: R-15 기록 저장 후, R-6 사전 질문 제출, R-36 문자 수신.
- 동작: 분류기가 원문을 사실 하나 단위로 분리 → 좋아하는 것·싫어하는 것·가치관·습관·성향 중 하나로 분류 → 각 사실을 R-18 병합 판정으로 넘긴다.
- 결과: 신규 사실은 카드 후보가 되고, 분류하기 어려운 사실은 카드로 만들지 않는다(원문은 기록 탭에 유지).
- 완료 조건: 정상 원문에서 사실이 0개 이상 추출되고, 추출된 각 사실에 카테고리 1개가 부여된다.

### R-18 AI 병합과 미분류 보관

- 입력·트리거: R-17이 만든 사실 후보.
- 동작: 병합 판정기가 같은 카테고리의 기존 카드와 의미 동일·포함 관계(예: "아이스 아메리카노" · "아메리카노" · "아아")를 판단 → 후보가 있으면 SCR-13(또는 알림)에서 "같은 정보로 볼까요?" 확인 → 승인 시 기존 카드에 출처만 추가, 거절 시 새 카드 생성. 후보가 없으면 새 카드 생성. 자동 병합은 하지 않는다.
- 결과: 카드 증식이 억제되고 병합은 사용자 결정으로만 확정된다.
- 완료 조건: 사용자 확인 전에는 병합이 확정되지 않는다. 분류 불가 사실은 카드로 만들지 않는다.
- 미결정: 병합 후보로 볼 유사도 기준과 확인 UX(인라인 vs 알림)(§6).

### R-19 분석 실패 복구

- 입력·트리거: R-17/R-18 처리 중 오류.
- 동작: 원문(기록·문자·사전 질문 응답)은 정상 저장 유지. 실패 사유가 네트워크·타임아웃 등 일시적 오류면 "다시 분석" 재시도를 제공하고, 그 외 사유는 재시도 없이 기록 탭에만 남긴다.
- 결과: 분석 실패가 원본 저장이나 다른 기능을 막지 않는다.
- 완료 조건: 일시적 오류에서만 재시도 버튼이 나오고, 재시도 성공 시 카드가 반영된다.

### R-20 카드 조회

- 입력·트리거: SCR-12 프로필 탭 진입.
- 동작: 본인이 작성·생성한 카드만 카테고리별로 목록화하고, 각 카드에 정보 내용과 출처(사전 질문·기록·문자)를 표시. 연인이 만든 카드는 조회되지 않는다. 조회·관리 전용이며 기록 작성 입구는 없다.
- 결과: 본인이 정리한 연인 정보가 카테고리별로 보인다.
- 완료 조건: 카드가 없는 카테고리는 빈 상태 안내가 뜬다. 저장·병합 직후 즉시 반영된다.

### R-21 카드 수정·삭제

- 입력·트리거: SCR-13 카드 상세에서 수정 / 삭제.
- 동작: 내용·카테고리 수정 → 사용자 수정 카드로 표시. 삭제 → 카드만 제거. 카드 수정·삭제는 출처 기록·문자 원문을 바꾸지 않는다.
- 결과: 사용자가 카드를 직접 관리한다.
- 완료 조건: 수정한 카드는 이후 AI가 덮어쓰지 않는다(R-22). 삭제해도 출처 기록·문자는 남는다.

### R-22 사용자 수정 보호·상반 정보

- 입력·트리거: 이후 분석에서 같은 주제의 사실이 유입될 때.
- 동작: 사용자가 수정한 카드는 자동 갱신 대상에서 제외. 상반된 정보(예: 좋아함 ↔ 싫어함)가 들어오면 최신 기록 기반 카드를 우선 후보로 노출한다.
- 결과: 사용자 편집이 보존되고, 최신 정보가 먼저 보인다.
- 완료 조건: 수정 카드가 재분석 후에도 유지된다. 상반 카드가 공존하되 최신 카드가 우선 표시된다.

### R-23 변경 즉시 반영

- 입력·트리거: 카드 수정·삭제·병합 발생.
- 동작: AI 채팅 컨텍스트, 아이템 제안 집계, 대표 문구 생성이 항상 최신 카드 상태를 참조하도록 한다.
- 결과: 카드 변경이 지연 없이 다른 기능에 반영된다.
- 완료 조건: 삭제한 카드 내용이 직후의 채팅 답변·대표 문구에 나타나지 않는다.

### R-24 미니유 AI 채팅

- 입력·트리거: SCR-06에서 연인 미니유 탭 → SCR-09. 커플 연결 상태 + 잔여 횟수 필요.
- 동작: 채팅 응답기가 프로필 카드 + 기록 + 문자 요약을 컨텍스트로 답변을 생성한다(요청 → 처리 → 응답).
- 결과: 답변이 표시되고 대화 로그가 저장된다.
- 완료 조건: 답변 생성이 끝나면 R-27이 1회 차감한다. 첫 응답 5초 이내를 목표로 한다.

### R-25 채팅 말투

- 입력·트리거: R-24 답변 생성 시 / SCR-10에서 말투 재설정.
- 동작: 말투 프로필이 있으면 6필드를 답변 프롬프트에 반영하고, 없으면 서비스 공통 기본 말투를 쓴다. 말투 프로필은 미니유 생성 이후에도 SCR-10에서 다시 설정·수정할 수 있다.
- 결과: 답변 문체가 말투 프로필을 따른다.
- 완료 조건: 말투 프로필 유무에 따라 문체가 달라진다. 이후 작성되는 기록·문자는 말투를 바꾸지 않는다.
- 미결정: 말투 요약을 프롬프트에 넣는 형식과 기본 말투 병합 규칙(§6).

### R-26 대화 캡처 말투 설정(선택)

- 입력·트리거: SCR-07 미니유 생성 중 또는 SCR-10 채팅 설정에서 대화 캡처 이미지 업로드(최대 4장).
- 동작: 말투 요약기가 연인이 보낸 메시지를 중심으로 말투 6필드를 요약해 말투 프로필로 저장(상태 = 준비됨). 원본 이미지는 분석 완료 직후 삭제. 커플 연결 해제 시 말투 프로필 자동 삭제. 분석 실패 시 기본 말투. 일부 파일 업로드 실패 시 성공한 파일을 먼저 반영하고 "N개 실패"를 알린다.
- 결과: 말투 프로필이 저장되고 R-25에서 사용된다.
- 완료 조건: 원본 캡처가 저장되지 않는다. 4장 초과 업로드는 차단된다. 재설정 시 이전 요약을 대체한다.

### R-27 채팅 사용량 제한

- 입력·트리거: R-24 답변 생성 완료 시.
- 동작: 일일 카운터를 +1 한다(최대 20). 20 도달 시 입력을 차단하고 다음 초기화 시각을 안내. 한국 시간 자정에 0으로 초기화. 응답 생성 실패는 차감하지 않는다.
- 결과: 하루 사용량이 제한되고 다음 날 다시 이용할 수 있다.
- 완료 조건: 20회까지는 정상, 21회째에 차단 안내가 뜬다. 잔여 횟수와 초기화 시점이 SCR-09에 상시 표시된다.

### R-28 홈 화면 구성

- 입력·트리거: 미니유 생성 후 SCR-06.
- 동작: 연인 미니유, 집 배경, 현재 착용 아이템, 집 방문하기 버튼을 표시. 커플 연결 전에는 집 방문 등 잠긴 요소를 비활성으로 표시.
- 결과: 홈이 연인 미니유와 진입점을 보여준다.
- 완료 조건: 착용 아이템이 없으면 기본 미니유를 렌더한다. 미연결 시 집 방문 버튼이 비활성 + 안내다.

### R-29 집 방문

- 입력·트리거: SCR-06 "집 방문하기" → SCR-08. 커플 연결 필요.
- 동작: 집 내부에서 연인 미니유 확인, 미니유 꾸미기(R-30), 애정표현 남기기(R-31), 연인 아이템 보관함 조회, 아이템 착용·해제를 제공.
- 결과: 사용자가 연인 미니유의 공간에서 상호작용한다.
- 완료 조건: 미연결 시 진입할 수 없고 연결 안내로 대체된다.

### R-30 미니유 꾸미기

- 입력·트리거: SCR-08 집 내부에서 외형·이름 편집.
- 동작: 커플 연결이 유지되는 동안 언제든 연인 미니유의 외형(헤어스타일·머리색·피부톤·얼굴형·표정)과 이름을 수정 → 저장 → 홈·채팅·공유 이미지에 반영.
- 결과: 미니유가 갱신된다.
- 완료 조건: 저장 즉시 반영된다. 연결 해제 후에는 미니유가 삭제 대상이므로 편집할 수 없다.

### R-31 애정표현

- 입력·트리거: SCR-08에서 껴안기 / 뽀뽀하기 / 쓰다듬기 선택.
- 동작: 짧은 애니메이션 + 완료 문구 → 활동 기록 → R-32 알림 트리거.
- 결과: 애정표현 활동이 저장되고 연인에게 전달된다.
- 완료 조건: 애니메이션 후 집 내부로 복귀하고, 활동이 로깅·알림에 남는다.

### R-32 애정표현 알림

- 입력·트리거: R-31 완료.
- 동작: 연인에게 인앱 알림을 전달. 같은 유형은 5분에 1건으로 제한(그 사이 활동은 묶어 표시). 사용자는 SCR-18 설정에서 애정표현 알림 수신 여부를 바꾼다.
- 결과: 연인이 애정표현 활동을 알림으로 확인한다.
- 완료 조건: 기본 수신은 켬. 5분 내 연타는 1건으로 합쳐진다. 수신 끔이면 알림을 만들지 않는다.

### R-33 문자 발송

- 입력·트리거: SCR-14에서 텍스트 입력(+ 이미지 선택 첨부, + 텍스트형 이모지) → 보내기. 커플 연결 필요.
- 동작: 문자를 저장·전송. 이미지 업로드 일부 실패 시 성공한 파일을 먼저 반영하고 "N개 실패"를 알린다. 스티커는 제공하지 않고, 텍스트형 이모지(예: OTL, ㅠㅠ) 팔레트를 제공한다.
- 결과: 연인의 문자 탭 뱃지가 증가하고 목록에 문자가 쌓인다.
- 완료 조건: 빈 문자 전송은 차단된다. 첨부 이미지는 문자에 함께 저장된다.
- 미결정: 이미지·이모지만 있고 텍스트가 없는 문자의 전송 허용 여부(§6).

### R-34 문자 조회·답장

- 입력·트리거: SCR-14 목록 조회 / 문자 상세에서 답장.
- 동작: 안 읽은 문자를 문자 탭 뱃지로 표시하되 읽음 여부는 표시하지 않는다. 답장은 새 문자로 저장하며 기존 문자와 스레드로 묶지 않는다.
- 결과: 문자를 확인하고 답장할 수 있다.
- 완료 조건: 상세 열람 시 뱃지가 감소한다(내부 읽음 처리, 연인에게는 미표시).

### R-35 문자 저장·공유

- 입력·트리거: 문자 상세에서 "저장" 또는 "공유".
- 동작: 문자를 카드형 이미지로 렌더해 파일로 내려받는다. 문자 "저장"은 이 카드형 이미지를 내려받는 것을 뜻한다.
- 결과: 문자 내용이 담긴 이미지 파일이 저장된다.
- 완료 조건: 내려받은 이미지에 문자 카드가 포함된다.

### R-36 문자 기반 정보 활용

- 입력·트리거: 연인이 보낸 문자 수신·저장 후.
- 동작: 분류기가 연인 문자에서 취향·습관 사실을 추출해 R-17/R-18과 동일 파이프라인으로 프로필 카드(5개 카테고리)에 반영하고 AI 채팅 답변에 활용. 선물 힌트 등 5개 카테고리에 없는 정보는 카드로 만들지 않는다. 문자 내용은 미니유 말투를 바꾸지 않는다.
- 결과: 문자에서 얻은 정보가 카드·채팅에 반영된다.
- 완료 조건: 문자 유래 카드에 `문자` 출처가 표시된다.
- 미결정: 문자 유래 카드의 출처·중복 처리 세부(§6).

### R-37 AI 아이템 제안

- 입력·트리거: 기록·카드 누적 시 배치 점검.
- 동작: 규칙 집계 — ① 기록 10개 이상 ② 같은 구체적 취향·사물 2회 이상 언급 ③ 착용하거나 들 수 있는 형태 → 취향 키워드를 아이템 세트에 매핑(예: 커피 → 테이크아웃 커피 컵, 야구 → 야구 모자·글러브, 기타 → 기타 액세서리) → SCR-15에 제안 → ④ 사용자 승인 시 인벤토리에 생성, 거절 시 보류. 추상적 감정은 아이템으로 만들지 않는다.
- 결과: 취향 기반 아이템이 인벤토리에 추가된다.
- 완료 조건: 4개 조건이 모두 충족되기 전에는 제안이 없다. 사용자 승인 없이는 아이템이 생성되지 않는다.
- 미결정: 아이템 에셋 세트와 취향 키워드 매핑 테이블(§6, 디자인·기술설계).

### R-38 인벤토리

- 입력·트리거: SCR-08 집 내부 인벤토리.
- 동작: 보유 아이템 목록(최대 10개)을 조회하고 착용/해제를 토글한다.
- 결과: 미니유의 착용 아이템이 바뀐다.
- 완료 조건: 11개째 생성은 차단된다(안내). 착용 변경이 홈·공유 이미지에 즉시 반영된다.

### R-39 공유 이미지 저장

- 입력·트리거: SCR-16 진입(미니유 생성 이후 언제든).
- 동작: 현재 미니유 씬(연인 미니유, 집 또는 정원 배경, 착용 아이템, 대표 문구, 선택형 D-day)을 렌더해 이미지 파일로 내려받는다. D-day는 사귄 날짜 기준이며 표시 여부를 사용자가 고른다. 실제 이름·문자 원문·기록 원문은 기본 이미지에 넣지 않는다.
- 결과: 미니유 씬이 한 장의 이미지로 저장된다.
- 완료 조건: 커플 연결·기록 누적을 추가로 요구하지 않는다(미니유가 있으면 가능). 개인정보가 노출되지 않는다.

### R-40 대표 문구

- 입력·트리거: SCR-16 대표 문구 영역.
- 동작: 대표 문구 생성기가 프로필 카드를 근거로 문구 3개를 제안 → 사용자가 하나를 고르거나 직접 입력. 프로필 카드가 없거나 생성이 실패하면 사용자가 직접 입력한다.
- 결과: 선택하거나 입력한 문구가 공유 이미지에 들어간다.
- 완료 조건: 기본 문구 세트는 없다. 문구가 비어 있으면 D-day·미니유만으로 이미지가 생성된다(문구 영역 생략).

### R-41 인앱 알림 센터

- 입력·트리거: SCR-17 진입 / 상단 알림 아이콘.
- 동작: 커플 연결 완료, 문자 수신, 애정표현 활동을 뱃지 + 목록으로 표시. 사용자는 SCR-18 설정에서 알림 유형별 수신 여부를 바꾼다. 웹·네이티브 푸시는 제공하지 않는다.
- 결과: 사용자가 활동을 한곳에서 확인한다.
- 완료 조건: 수신을 끈 유형은 알림을 생성하지 않는다. 알림 확인 시 뱃지가 감소한다.
- 미결정: 수신을 끈 유형의 목록 적재 여부(§6).

### 5.2 읽기·쓰기 주체

- 온보딩·계정·세션: 본인만.
- **연인에 대한 기록·프로필 카드·사전 질문 응답·AI 채팅·말투 프로필: 작성·생성한 본인만 읽고 쓴다.** 커플로 연결되어도 연인에게 노출되지 않는다(기록 비공개 원칙).
- 연인 미니유·미니유 집·아이템/인벤토리·공유 이미지: 각 사용자가 자기 계정의 것을 만들고 꾸민다(상대의 것을 편집하지 않는다).
- 문자: 발신자가 작성하고 수신자(연인)가 읽는다. 애정표현: 본인 공간에서 수행하고 연인에게는 활동 알림만 전달된다.
- 초대 코드 수락: 로그인된 다른 사용자(본인 코드·이미 연결된 계정은 불가).
- 말투 프로필: 시스템이 캡처 분석으로 쓰고, 사용자가 SCR-10에서 재설정한다. 본인의 AI 채팅에만 쓰인다.
- AI(분류기·병합 판정기·말투 요약기·채팅 응답기·대표 문구 생성기): **해당 사용자 본인의** 기록·카드·문자·캡처를 읽어 그 사용자의 카드·말투·답변·문구를 만든다. 병합 확정과 아이템 생성은 사용자 승인이 있어야 한다.

### 5.3 민감 정보

- 문자·기록·대화 캡처는 민감 개인 데이터. 전송 구간 암호화, 대화 캡처 원본은 분석 직후 삭제.
- 공유 이미지 기본형에 실제 이름·문자 원문·기록 원문을 넣지 않는다.
- 커플 연결 해제·계정 삭제는 대상·30일 유예·복구 불가를 사전 안내하고 유예 후 완전 삭제한다.
- 지속 상태는 서버에 저장하고 브라우저 storage를 신뢰 저장소로 쓰지 않는다.
- 저장 구간 암호화 수준·보관 기간은 배포 전 법적 검토 대상(§6).
