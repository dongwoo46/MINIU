# MINIU(미니유) 개인정보·법적 처리 검토 (v1)

기준 문서: `docs/features/miniu/prd.md`(PRD v3), `docs/features/miniu/spec.md`(기능명세서 v2). 작성일 2026-09-10.

> **면책**: 본 문서는 위 PRD/기능명세서를 근거로 한 **내부 사전 검토**이며 **법률 자문이 아니다**. 대한민국 「개인정보 보호법」(이하 PIPA, 2023·2024 개정 반영)과 관련 규정을 참고했으나, 해석이 갈리는 지점은 `[법률 검토 필요]`로 표시했다. **서비스 출시 전 개인정보·IT 전문 변호사(또는 개인정보 컨설팅)의 최종 검토가 반드시 필요하다.**

## 0. 검토 전제

- 출시 형태: 대한민국 일반 이용자 대상 **웹 서비스**, 무료(결제 없음).
- 개인정보처리자 = 미니유 운영 주체(법인/개인). 개인정보 보호책임자(CPO) 지정 필요.
- 기준 법령: PIPA / 「개인정보의 안전성 확보조치 기준」 / 정보통신망법(영리목적 광고성 정보) / (해당 시) 통신비밀보호법.
- **인증 방식은 이메일+비밀번호 회원가입 + 이메일 인증으로 확정**한다. 구글 등 **소셜 로그인은 도입하지 않는다**(PRD §3.3, §4.1 R-1, §7.1 / 스펙 R-1·R-2와 일치). 따라서 소셜 로그인에 따른 제3자 경유·국외 이전 이슈는 본 검토 범위에서 제외한다. 향후 도입 시 별도 검토가 필요하다.
- 외부 서비스 가정: 클라우드 인프라·객체 스토리지 / **외부 AI API**(OpenAI GPT 또는 Google Gemini 등 — AI 분석용 API이며 로그인과 무관) / 이메일 발송 서비스.

### 용어 구분(본 문서에서)

| 구분 | 의미 |
|---|---|
| 동의 | PIPA상 정보주체의 명시적 동의가 **법적으로 요구**되는 처리 |
| 고지(처리방침) | 동의 없이 처리 가능하되 **개인정보 처리방침 공개/통지**로 충족 |
| 계약이행 근거 | PIPA §15①4호 — 계약 체결·이행에 불가피한 최소 정보는 동의 없이 처리 가능 |
| 관행적 동의 | 법적으로 필수는 아니나 국내 관행상 받는 동의(과다 동의 주의) |

### 1-A. 소셜 로그인

- **구글 등 소셜 로그인은 도입하지 않는다.** 인증은 이메일+비밀번호 + 이메일 인증만 사용한다. 따라서 인증 제공자(구글 등)로의 개인정보 경유·국외 이전 이슈는 발생하지 않는다.
- 향후 소셜 로그인을 도입한다면, 인증 제공자로부터 수집하는 항목(이메일·계정 식별자 등)의 최소화, 처리방침의 국외 이전 공개, 별도 동의 요부를 **그때 별도로 검토**해야 한다.

### 1-B. 주민등록번호·고유식별정보

- 미니유는 주민등록번호/여권번호/운전면허번호/외국인등록번호, 휴대폰 본인확인(CI/DI)을 **수집하지 않는다** → 고유식별정보 처리 없음(§24). 이 상태를 유지할 것. 향후 본인확인 도입 시 별도 검토.

## 2. 상대방(연인) 정보 — 제3자 개인정보

미니유의 핵심 데이터는 **이용자가 입력·업로드하는 "제3자(연인)에 관한 개인정보"**다. 이는 국내 서비스에서 명확한 가이드라인이 부족한 회색지대이며 **가장 큰 법적 리스크**다. `[법률 검토 필요]`

### 2.1 항목별 검토

| 데이터 | 개인정보 | 민감정보 해당 가능성 | 설명 |
|---|---|---|---|
| 연인 이름/닉네임 | **O**(제3자) | 아님 | 실명이면 식별성 강함. 커플 연결 시 상대 계정과 결합되어 식별성 극대화 |
| 연인 취향(일반) | **O**(제3자, 특정 개인에 관한 정보) | 원칙적으로 아님 | "특정 개인에 관한" 정보이므로 개인정보. |
| 좋아하는 것 / 싫어하는 것 | **O** | **조건부** | 내용에 따라 종교(무교·특정 종교), 정치 성향, 성적 지향, 건강(질환·식이) 노출 시 **민감정보**(PIPA §23) |

| 일상생활 정보 | **O** | 조건부 | 거주·직장·이동 패턴 등 |

| 대화 스크린샷(이미지) | **O** | **높음** | 위 + 화면에 이름·전화번호·프로필 사진·타인 정보 포함 가능 → §4 |

### 2.2 핵심 쟁점: 이용자가 제3자(연인)의 개인정보를 입력

- **정보주체(연인)의 동의를 미니유가 직접 받기 어렵다.** 커플 연결 전에는 연인이 미가입자이고, 연결 후에도 "상대가 나에 대해 무엇을 적었는지"를 사전 통제하기 어렵다.
- **[제품 결정] 기록·프로필 카드·AI 채팅은 작성한 본인만 열람하는 비공개 방식(옵션 B)으로 확정**(PRD §5.2, 스펙 §1.4·§5.2). 이 방식은 연인 간 노출을 막지만, **연인이 자기 정보가 어떻게 기록·분석되는지 전혀 볼 수 없어 투명성·열람권 측면에서는 더 취약**하다. 따라서 아래 4·5·6번 조치(제3자 삭제 요청 채널, 입력 화면 고지, 즉시 삭제)의 중요도가 커진다.
- PIPA는 "정보주체 이외로부터 수집한 개인정보"의 출처·목적·처리정지 요구권 고지 의무를 둔다(§20). 다만 미니유는 이용자를 통해 간접 수집하는 구조 → 적용 방식 `[법률 검토 필요]`.
- 유사 사례(연락처 업로드, 지인 추천, 후기에 타인 언급, 가계부에 지인 기재)에서 통상적으로 취하는 대응:
  1. **약관에 이용자 책임 조항**: "회원은 제3자(연인 등)의 개인정보를 입력·업로드할 정당한 권한이 있어야 하며, 필요한 경우 그 제3자의 동의를 받아야 한다. 제3자의 권리 침해로 인한 책임은 회원에게 있다."
  2. **입력 화면 고지**: 사전 질문·기록·캡처 업로드 화면 상단에 "연인이 원치 않을 민감한 정보(건강·종교·정치·성생활 등)나 제3자의 정보는 넣지 마세요" 취지 안내.
  3. **커플 연결 시 상호 고지·동의**: 연결 수락 화면에서 "연결하면 상대가 나에 대한 정보를 기록·분석할 수 있다(각자의 기록·카드는 비공개)"를 양쪽에 고지하고 **연결 자체에 대한 동의**를 받는다(스펙 R-9 보강).
  4. **제3자 삭제 요청 채널**: 처리방침에 "본인에 관한 기록의 삭제·처리정지를 요청할 수 있는 연락처"를 명시하고, 연인(제3자)이 요청 시 해당 기록·카드를 파기하는 절차를 마련.
  5. **최소 수집·즉시 삭제**: 대화 캡처 원본 즉시 삭제(PRD에 이미 존재) 유지·강화.
  6. **미연결로 방치된 사전 질문 응답**: 연인이 끝내 가입하지 않으면 순수 제3자 정보만 서버에 남는다 → **일정 기간(예: 30일) 미연결 시 파기** 정책 필요(현 PRD·스펙 미정의).

### 2.3 미니유가 해야 할 안내/조치 요약

| 커플 연결 시 상호 고지·동의 | 연결 수락 화면 동의 체크 | **필수** |

## 3. 대화 및 AI 기능 — 처리위탁 / 제3자 제공 / 국외 이전

### 3.1 외부 AI API로 전송될 수 있는 데이터

| 기능(스펙) | AI로 가는 데이터 | 개인정보 | 민감 가능성 |

### 3.2 처리위탁 / 제3자 제공 / 국외 이전 판단

| 성격 | 성립 조건 | 미니유의 경우 |
|---|---|---|
| **처리위탁**(§26) | 미니유의 **목적·지시에 따라** AI사가 처리하고, AI사가 **자기 목적으로 이용하지 않음** | AI API를 "미니유 기능 제공 목적"으로만 호출하고, **AI사가 입력을 자사 모델 학습·자기 목적에 쓰지 않는 조건**이면 → **처리위탁**. 동의 불요, **처리방침에 수탁자·위탁업무 공개**(§26②)로 충족. |
| **제3자 제공**(§17) | 제공받는 자가 **자신의 목적·이익**을 위해 처리 | AI사가 **입력 데이터를 모델 학습·품질 개선·자체 활용**하면 → **제공** 성격 + 목적 외 이용 → **별도 동의 필요**(사실상 채택 곤란). |
| **국외 이전**(§28-8) | 개인정보가 국외로 이전·처리·보관됨 | OpenAI(미국)/Anthropic(미국)/Google(미국 등) API 호출 시 **국외 이전 발생**. |

**국외 이전 동의 요부(§28-8):**
- 원칙: 정보주체 **동의**.
- 예외(동의 갈음): **§28-8①3호** — 정보주체와의 **계약 체결·이행**을 위해 **처리위탁·보관**이 필요하고, 이전 관련 사항(이전받는 자, 항목, 국가, 시기·방법, 이용목적·보유기간 등)을 **개인정보 처리방침에 공개**하거나 통지한 경우 → **별도 동의 없이 국외 이전 가능**.
- 따라서 **AI API가 "위탁 + 학습 미사용"이고, 처리방침에 국외 이전 사항을 공개**하면 국외 이전 별도 동의는 **법적으로는 불요**할 수 있다. `[법률 검토 필요]`
- 다만 **대화 스크린샷/대화 내용처럼 민감도가 높은 데이터의 국외 전송**은 보수적으로 **별도 동의를 받는 것을 권고**한다(위험 대비, 이용자 신뢰).

### 3.3 동의 필요 vs 처리방침 고지 (요약)

| 사안 | 결론(잠정) |
|---|---|
| AI API로의 개인정보 전송(위탁) | **처리방침 고지**로 충족(수탁자·업무 공개). 동의 불요 `[법률 검토]` |
| AI API 국외 이전(위탁+학습 미사용+처리방침 공개) | **처리방침 공개로 동의 갈음** 가능 `[법률 검토]` |
| AI API가 데이터를 학습·자기 목적 이용 | **제3자 제공/목적 외 이용 → 별도 동의 필요.** 원칙적으로 **이런 벤더·플랜은 채택하지 않음** |
| 대화 캡처/대화 내용의 국외 전송 | 보수적으로 **국외 이전 별도 동의 권고** `[법률 검토]` |
| 민감정보(가치관·건강 등)가 AI로 전송 | **민감정보 처리 별도 동의** 또는 **민감정보 미입력 설계** `[법률 검토]` |
| 자동화 분석(카드 분류·추천) | §37-2 "중대한 영향" 아닐 가능성 높음 → 거부권 대상 아님. 단 **분석 기준·절차를 처리방침에 공개** 권장 `[법률 검토]` |

### 3.4 OpenAI(GPT) vs Google(Gemini) 등 차이

| 구분 | OpenAI API | Anthropic API | Google Gemini API |
|---|---|---|---|
| 학습 사용(기본) | API 입력·출력을 **기본적으로 모델 학습에 미사용**(별도 opt-in 없으면) | 입력·출력을 **기본적으로 학습에 미사용** | **유료(paid) 등급은 학습 미사용**. **무료 등급(AI Studio 등)·일부 지역은 학습·사람 검토에 사용될 수 있음** → **반드시 유료 등급 + 데이터 보호 약정** |
| 데이터 보관 | 남용 모니터링 목적 단기 보관(정책상 약 30일), **Zero Data Retention(ZDR)** 계약 시 미보관 | 유사(안전 목적 단기 보관, 조건부 ZDR) | 플랜·설정에 따라 상이 |
| 처리 위치 | 미국 등(국외) | 미국 등(국외) | 미국 등(국외), 리전 옵션 존재 여부 확인 |
| 계약 | **DPA(데이터 처리 부속 계약) 체결 필요** | **DPA 체결 필요** | **DPA + 유료 등급 필수** |
| 실무 결론 | 위탁으로 구성 가능, DPA·ZDR 검토 | 위탁으로 구성 가능, DPA 검토 | **무료/AI Studio 사용 금지**, 유료 + DPA 필수 |

> 어떤 벤더든 **① API 티어에서 "학습 미사용" 계약상 확인, ② DPA 체결, ③ 가능하면 데이터 최소보관/ZDR, ④ 처리방침에 수탁자·국외 이전 공개**를 이행해야 위탁으로 안전하게 구성된다. 벤더의 실제 약관·기본값은 수시로 바뀌므로 **계약 시점에 재확인** `[법률 검토 필요]`.

## 4. 이미지 업로드 (대화 스크린샷)

| 항목 | 검토 |

| 이미지 자체의 개인정보성 | **개인정보 O.** 대화 캡처는 본인+연인의 대화, 화면 UI에 이름·닉네임·프로필 사진·전화번호·타인 대화가 포함될 수 있음. |

| AI 분석 위한 외부 전송 | 멀티모달 AI API로 **이미지 원본이 국외 전송**됨(R-26). → 위탁 + 국외 이전. 민감도가 높아 **별도 동의 권고** `[법률 검토]`. |
| 저장 여부 | **PRD/스펙상 원본 미저장**(R-14, R-26): 분석에만 사용, 서비스에는 **말투 요약(JSON)만 저장**. → 리스크가 크게 낮아지는 좋은 설계. |
| 분석 후 원본 삭제 | **분석 완료 직후 삭제**(R-26). 삭제가 실제로 일어났는지 **검증 로그/증적**을 남길 것(감사 대응). |
| 보관 기간 | 원본: **0(즉시 삭제)**. 말투 요약: **커플 연결 해제 시 자동 삭제**(R-26), 재설정 시 대체. |

| 업로드 전 조치 | 업로드 화면에 **사전 고지 모달**: "스크린샷은 말투 분석에만 쓰이고 분석 직후 원본이 삭제됩니다. 전화번호·타인 정보가 보이면 가리고 올려주세요." + (권고) 클라이언트단 자동 마스킹은 MVP 범위 밖. |

## 5. AI가 생성·추론하는 정보

| 정보 유형 | 개인정보 | 민감정보 가능성 | 고지/동의 |
|---|---|---|---|
| 사용자가 직접 입력한 정보(기록·사전 질문·문자) | **O**(본인/제3자) | 조건부 | 수집·이용 동의 + 연인 정보 처리 고지 |
| AI가 **분류**한 정보(5개 카테고리 카드) | **O**(연인에 관한, 미니유가 생성) | 카테고리 내용이 신념·건강이면 민감 | 처리방침에 "이용자 입력을 AI가 분류·카드화한다" 고지. 자동화 처리 기준·절차 공개 권장 |
| AI가 **추론**한 정보(명시되지 않은 성향·관심사 도출) | **O**(추론된 개인정보) | 추론으로 건강·심리·신념이 도출되면 **민감정보 생성** | 추론 사실·범위를 처리방침에 고지. 민감정보 추론이면 별도 동의 `[법률 검토]` |
| **말투 프로필**(분위기·어미·표현·이모지·답변 길이·반응 방식) | **O**(특정인의 언어적 특징) | 생체인식정보는 **아님**(음성 아님, 텍스트 스타일). 다만 개인 식별·특징 정보 | 캡처 업로드 시 목적·삭제·국외 이전 고지. 별도 동의 권고(민감 이미지 기반) |
| 대표 문구·공유 이미지 | 연인 특징 반영 → **개인정보 포함 가능** | 낮음(PRD상 실명·원문 미노출) | 처리방침 고지 |

**정리:**
- **AI가 만든 정보도 "특정 개인(연인)에 관한 정보"이면 개인정보**이고, PIPA의 수집·이용·보관·파기·정보주체 권리 규정이 그대로 적용된다.
- AI 추론으로 **민감정보가 새로 생성**될 수 있다는 점을 이용자에게 고지하고, 가능하면 **민감 카테고리 추론을 차단/제외**하도록 프롬프트·후처리를 설계할 것.
- §37-2(자동화된 결정): 미니유의 분류·추천은 정보주체 권리·의무에 "중대한 영향"을 미치는 결정으로 보기 어려워 **거부권·설명요구권의 직접 대상은 아닐 가능성**이 크다. 그러나 **자동화 처리의 개요·기준을 처리방침에 공개**하고, 이용자가 카드를 수정·삭제할 수 있게 한 현재 설계(R-21)는 바람직하다. `[법률 검토 필요]`

## 7. 필수 동의 vs 선택 동의

### 7.1 필수 (서비스 제공에 불가피 — 미동의 시 가입 불가 정당)

| 항목 | 법적 성격 |
|---|---|
| **서비스 이용약관 동의** | 계약 성립 |
| **개인정보 수집·이용 동의(필수 항목)** — 이메일, 비밀번호(해시), 이름/닉네임, 생년월일(연령확인), 커플 연결 정보, 최소 접속 로그 | 계약이행(§15①4호)으로도 가능하나 관행상 필수 동의로 구성. **단 실제로 필수인 항목만 포함** |
| **연인(제3자) 정보 처리 및 이용자 책임 고지** | 약관 조항 + 입력 화면 고지. 별도 동의 항목화 여부 `[법률 검토]` |
| **AI 기능 이용 및 개인정보 처리위탁·국외 이전 안내** | 처리방침 고지로 충족 가능. **대화 캡처·대화 내용의 국외 이전은 별도 동의 권고** `[법률 검토]` |
| **커플 연결 상호 동의** | 연결 수락 화면에서 "상대의 기록·분석 대상이 됨"에 동의 |
| **만 14세 미만 처리** | 법정대리인 동의(§22-2) 또는 **만 14세 미만 가입 차단**(MVP 권장) |
| **민감정보 처리 동의** | 사전 질문(가치관)·자유 서술·대화 캡처에 민감정보가 유입되는 구조이면 별도 동의 필요할 수 있음. **또는 민감정보 미입력 설계로 회피** `[법률 검토 필요]` |

### 7.2 선택 (미동의해도 서비스 이용 가능해야 함)

| 항목 | 근거 |
|---|---|
| **마케팅·광고성 정보 수신 동의**(이메일 등) | 정보통신망법 §50 opt-in. 2년마다 유지 확인. **야간(21~08시)에는 광고성 정보를 발송하지 않으므로 야간 수신 동의는 두지 않는다**(§50③) |
| **서비스 개선·통계 목적의 이용기록 상세 분석**(필수 최소 범위 초과분) | 목적 외/추가 이용 → 선택 |
| **인앱 알림 중 광고성 알림** | 서비스 알림(문자 수신 등)은 필수, 광고성은 선택 |

### 7.3 "법적으로 필수가 아닌데 필수로 받으면 안 되는 것" (과다 동의 경고)

| 항목 | 지적 |
|---|---|
| 마케팅 수신을 필수 동의에 끼워 넣기 | **금지**(선택 강제 = §16③ 위반) |
| **실명**을 필수로 요구 | 서비스상 실명 불필요 → **닉네임 허용**. 실명 필수화는 최소수집 원칙 위반 소지 |
| **생년월일 전체**를 받으며 목적을 "연령확인"으로만 두는 경우 | 연·월 또는 연도로 충분한지 검토. 생일 기능 없이 전체 수집 시 과다 |
| **AI 학습 이용 동의**를 필수로 묶기 | **금지**. 학습 이용은 서비스 제공에 불필요 → 필수화 불가(애초에 학습 미사용 벤더 사용 권장) |
| 위치정보·주소록·전화번호 | 미니유 기능에 불필요 → **수집하지 말 것** |
| "전체 동의" 1개 체크로 필수+선택 일괄 동의 | 필수/선택을 **구분 표시**하고 개별 체크 가능해야 함 |

## 8. 동의 항목별 상세 (회원가입/약관 반영용)

> 아래 문구는 **초안**이며 최종본은 `[법률 검토 필요]`. 보유기간·수탁자·국가는 실제 계약 확정 후 채운다.

### 8.1 서비스 이용약관 동의 (필수)

- 목적: 서비스 이용 계약의 체결 및 이행
- 항목: 해당 없음(약관 자체)
- 보유·이용 기간: 회원 탈퇴 시까지
- 제3자 제공: 없음 / 처리위탁: 없음 / 국외 이전: 없음
- 법적 근거: 계약 성립
- 짧은 문구: `[필수] 미니유 서비스 이용약관에 동의합니다. (전문 보기)`
- 상세: 서비스 내용, 회원의 의무(**제3자(연인) 정보 입력 시 정당한 권한·동의 확보 책임 포함**), 금지행위, 책임 제한, 계약 해지·탈퇴, 준거법·관할 등.

### 8.2 개인정보 수집·이용 동의 — 필수 항목 (필수)

- 목적: 회원 식별·인증, 서비스 제공(커플 연결, 기록·프로필·채팅·문자 등), 문의 응대, 법령상 의무 이행, 부정이용 방지·보안
- 수집 항목: 이메일, 비밀번호(해시), 이름 또는 닉네임, 생년월일(연령 확인), 커플 연결 정보(초대 코드, 연결 상대 식별자, 사귄 날짜), 서비스 이용기록·접속 로그(IP, 기기·브라우저 정보, 접속 일시)
- 보유·이용 기간: **회원 탈퇴 후 [30일 유예] 뒤 파기**. 단 접속 로그는 [1년], 관계 법령상 보존 의무가 있는 항목은 해당 기간 `[법률 검토]`
- 제3자 제공: 없음
- 처리위탁: 클라우드 인프라([사업자·국가]), 이메일 발송([사업자·국가]) — 처리방침에 공개
- 국외 이전: (위탁사가 국외인 경우) 처리방침 국외 이전 항목에 공개
- 법적 근거: PIPA §15①1호(동의) 및 §15①4호(계약 이행)
- 짧은 문구: `[필수] 개인정보 수집·이용에 동의합니다 (이메일, 비밀번호, 닉네임, 생년월일, 커플 연결 정보, 이용기록 / 보유: 탈퇴 후 30일). (자세히)`
- 상세: 위 표 그대로 + "동의를 거부할 수 있으나, 거부 시 회원가입이 제한됩니다."

### 8.3 연인(제3자) 정보 처리 안내 및 이용자 책임 (필수 — 고지 + 확인)

- 목적: 이용자가 입력·업로드하는 연인 관련 정보(취향·성향·습관·가치관·일상·대화·스크린샷)를 통한 기록·AI 분석 기능 제공
- 수집 항목: 이용자가 입력하는 연인의 이름/닉네임, 취향·성향·습관·가치관, 일상 정보, 대화 내용·스크린샷, 사귄 날짜 및 이로부터 AI가 분류·추론·생성하는 정보
- 보유·이용 기간: 커플 연결 해제 시 삭제(30일 유예), 이용자가 개별 삭제 시 즉시, 미연결 방치 시 [30일] 후 파일 `[법률 검토]`
- 제3자 제공: 없음 / 처리위탁: AI 분석(§8.4) / 국외 이전: §8.4
- 법적 근거: 이용자와의 계약 이행 + 이용자의 제3자 정보 제공. 제3자(연인) 본인 동의 확보 책임은 이용자 `[법률 검토 필요]`
- 짧은 문구: `[필수] 연인에 대한 정보를 입력할 때는 정당한 권한이 있어야 하며, 민감한 정보(건강·종교·정치·성생활 등)나 연인이 원치 않는 정보는 입력하지 않습니다. 연인 본인은 자신에 관한 기록의 삭제를 요청할 수 있습니다. (자세히)`
- 상세: 제3자 정보 처리 방식, **회원의 기록·카드는 비공개(연인에게 공개되지 않음)**, 연인의 삭제·처리정지 요청 연락처, 이용자 책임과 면책.

### 8.4 AI 기능 이용 및 개인정보 처리위탁·국외 이전 (필수 — 고지 / 캡처·대화는 별도 동의 권고)

- 목적: 기록·문자·대화 캡처를 분석해 프로필 카드 생성·병합, 미니유 말투 설정, AI 채팅 답변, 대표 문구 생성
- 이전/위탁 항목: 기록·사전 질문·문자 텍스트, 프로필 카드 내용, **대화 캡처 이미지 원본**, AI 채팅 입력, 말투 프로필
- 이전받는 자: [AI 사업자명] (예: OpenAI, L.L.C. / Google LLC 등) — 확정 후 기재
- 이전되는 국가: [미국 등]
- 이전 시기·방법: 서비스 이용 중 해당 기능 실행 시, HTTPS API 호출을 통해 전송
- 이전받는 자의 이용 목적: 미니유의 요청 처리(분석 결과 반환)에 한함. **모델 학습·자기 목적 이용 금지(DPA로 확약)**
- 보유·이용 기간: AI 사업자 측 **미보관 또는 남용 모니터링 목적 단기 보관 후 삭제**([ZDR/보관정책 확정])
- 처리위탁 근거: PIPA §26 (처리방침에 수탁자·업무 공개)
- 국외 이전 근거: PIPA §28-8①3호 (계약 이행 목적 위탁·보관 + 처리방침 공개) `[법률 검토]` — **대화 캡처·대화 내용은 별도 국외 이전 동의를 받는 방안 권고**
- 짧은 문구(고지형): `[필수] 원활한 AI 기능 제공을 위해 입력하신 기록·문자·대화 캡처가 국외(미국 등) AI 처리 사업자에게 전송·처리됩니다. 해당 사업자는 데이터를 모델 학습에 사용하지 않으며, 대화 캡처 원본은 분석 후 즉시 삭제됩니다. (자세히)`
- 짧은 문구(동의형, 캡처/대화 대상): `[필수] 대화 및 대화 캡처의 국외 이전(AI 분석)에 동의합니다.`
- 상세: 위 항목 전체 + 거부 시 해당 AI 기능 이용 제한, 캡처 미업로드 시 기본 말투 적용.

### 8.5 민감정보 처리 (조건부 — [법률 검토 필요])

- 쟁점: 사전 질문 "가치관", 자유 서술 기록, 대화 캡처에 사상·신념·건강·성생활 등 민감정보가 유입될 수 있음.
- 선택지 A(회피): "가치관" 질문을 취향 중심으로 재설계하고 종교·정치·성적 지향·건강 예시를 배제 + "민감정보를 입력하지 말라"는 고지 → **민감정보 별도 동의 불요** 목표
- 선택지 B(수용): 민감정보 처리 별도 동의 항목 추가(§23) — `[필수] 대화·기록에 포함될 수 있는 민감정보(건강·신념 등)의 처리에 동의합니다.`
- 권고: **선택지 A 우선**, 불가 시 B. 최종 판단 `[법률 검토 필요]`

### 8.6 만 14세 미만 (필수 — 차단 또는 법정대리인 동의)

- MVP 권고: 생년월일로 **만 14세 미만 가입 차단**. 문구: `만 14세 미만은 가입할 수 없습니다.`
- 차단하지 않을 경우: 법정대리인 동의 절차(법정대리인 성명·연락처 최소 수집, 동의 확인 수단) 필요 → MVP 범위 과다.

### 8.7 마케팅·광고성 정보 수신 (선택)

- 목적: 이벤트·혜택·신규 기능 등 광고성 정보 발송(이메일 등)
- 항목: 이메일, (발송 최적화용) 서비스 이용 기록
- 기간: 동의 철회 시 또는 회원 탈퇴 시까지, **2년마다 수신 동의 유지 여부 확인**
- 법적 근거: 정보통신망법 §50 (사전 동의)
- 짧은 문구: `[선택] 마케팅·광고성 정보 수신에 동의합니다.` (야간 21~08시에는 발송하지 않으므로 야간 수신 동의는 두지 않음)
- 상세: 발송 채널, 철회 방법(무료), 미동의 시에도 서비스 이용에 제한 없음 명시.

- (3)은 "안내 확인" 성격(처리방침 고지로 충족 가능), (4)는 민감도가 높아 **회원가입 시 필수 동의**로 받고 캡처 업로드 화면에서 재고지한다. (4)를 처리방침 공개로 갈음 가능한지는 `[법률 검토 필요]`.

- 소셜 로그인은 도입하지 않으므로, 위 이메일 회원가입 흐름이 유일한 가입 경로다.

### 10.1 전체 흐름

[이용자 브라우저]

[외부 AI API]  (OpenAI / Anthropic / Google 등, 국외)   ◀── 위탁, 국외 이전
   전송: 기록·사전질문·문자 텍스트, 카드 내용, 캡처 이미지 원본, 채팅 입력, 말투 프로필

## A. 해커톤 MVP에서 반드시 구현해야 하는 법적/동의 UX (개발 상세)

> 목표: **동의를 받고, 무엇에 언제 어떤 버전으로 동의했는지 저장**하고, **삭제·탈퇴가 실제로 동작**하게 한다.

### A-1. 동의 데이터 모델

`UserConsent` (동의 1건당 1행, append-only 이력)

| 필드 | 설명 |
|---|---|
| `id` | PK |
| `userId` | FK |
| `consentType` | `TERMS` / `PRIVACY_REQUIRED` / `THIRD_PARTY_PARTNER_NOTICE` / `AI_PROCESSING_NOTICE` / `OVERSEAS_TRANSFER` / `SENSITIVE`(사용 시) / `AGE_14_OVER` / `MARKETING` (야간 발송 안 하므로 `MARKETING_NIGHT` 없음) |
| `version` | 해당 약관/처리방침 문서 버전 (예: `terms-2026-09-10`) |
| `agreed` | boolean |
| `agreedAt` | timestamp |
| `ip`, `userAgent` | 동의 시점 접속 정보 |
| `revokedAt` | 철회 시각(선택 항목) |

- 저장 시점: 회원가입 완료 트랜잭션에서 각 항목 1행 insert.
- 철회: `MARKETING` 등은 새 행(`agreed=false`) 또는 `revokedAt` 갱신.
- 재동의: 문서 `version`이 올라가면 로그인 후 재동의 모달 → 새 행 insert.

`LegalDocument` (약관/처리방침 본문·버전)

| 필드 | 설명 |
|---|---|
| `type` | `TERMS` / `PRIVACY` / `OVERSEAS` … |
| `version` | 문자열 |
| `effectiveFrom` | 시행일 |

### A-2. 회원가입 화면 컴포넌트

- `<SignupForm>`
  - `<TextField name=email>` `<PasswordField>` `<TextField name=nickname>`
  - `<BirthdatePicker>` → onChange 시 만 나이 계산. **만 14세 미만이면** `<AgeBlockNotice>` 표시 + 제출 차단.
- `<ConsentGroup>`
  - `<ConsentAllCheckbox>` — 하위 전체 토글(필수+선택). 개별 해제 허용.
  - 필수 그룹: `<ConsentItem required id=TERMS>` `<ConsentItem required id=PRIVACY_REQUIRED>` `<ConsentItem required id=AI_PROCESSING_NOTICE>` `<ConsentItem required id=OVERSEAS_TRANSFER>`(대화·캡처 국외 이전) `<ConsentItem required id=THIRD_PARTY_PARTNER_NOTICE>` `<ConsentItem required id=AGE_14_OVER>`
    - (설계 확정 시) `<ConsentItem required id=SENSITIVE>` — "가치관" 문항 재설계로 회피 가능하면 미사용 `[법률 검토]`
  - 선택 그룹: `<ConsentItem id=MARKETING>` (야간 발송을 하지 않으므로 야간 수신 동의 항목 없음)

- `<SubmitButton disabled={!allRequiredChecked || ageUnder14}>`
- 제출 → API가 계정 생성 + `UserConsent` 다건 insert + 인증 메일 발송.

### A-4. 대화 캡처 업로드 플로우

- 업로드 버튼 클릭 → `<CaptureUploadConsentModal>` (최초 1회 필수 확인)
  - 내용: 목적(말투 분석 전용), **원본은 분석 직후 삭제**, 국외 AI로 전송됨, 전화번호·타인 정보 마스킹 권고.
  - `[확인하고 업로드]` 클릭 시 `UserConsent(consentType=OVERSEAS_TRANSFER 또는 CAPTURE_UPLOAD)` 기록. `[법률 검토]`로 별도 동의 항목화 여부 결정.
- 서버: 이미지 수신 → AI 분석 호출 → **성공/실패와 무관하게 원본 파일 삭제** → 삭제 이벤트 로그(`captureId`, `deletedAt`) 기록(원문 없이).
- 부분 실패: 성공분만 반영 + "N개 실패" 토스트(R-26).

### A-5. 정보주체 권리 화면 (설정 > 개인정보)

- `<DataRightsPage>` (`/settings/privacy`)
  - **기록 삭제**: 기록 탭에서 개별 삭제(R-16) — 연동 카드 함께 삭제.
  - **카드 삭제/수정**: R-21.
  - **말투 프로필 삭제**: 명시적 버튼 추가(현재 재설정만 있음).
  - **커플 연결 해제**: R-11, 삭제 대상·30일 유예·복구 불가 고지.
  - **회원 탈퇴**: R-2, 30일 유예 안내 + 유예 중 재로그인 시 취소.
  - **내 데이터 열람/내보내기**: MVP는 "가입 정보 + 내 기록 목록" 조회 수준이라도 제공(다운로드는 후속).
  - **제3자(연인) 삭제 요청 안내**: "연인 본인은 [이메일]로 자신에 관한 기록의 삭제를 요청할 수 있습니다."

### A-6. 커플 연결 수락 화면 (R-9 보강)

- `<ConnectConsentModal>`: "연결하면 상대가 나에 대한 정보를 기록·분석할 수 있습니다. (서로의 기록·카드는 비공개이며, 문자·애정표현만 주고받습니다.)" + `[동의하고 연결]`.
- `UserConsent(consentType=COUPLE_LINK_MUTUAL)` 기록.

### A-7. 법률 페이지 라우트

- `/legal/terms`, `/legal/privacy`, (해당 시) `/legal/overseas-transfer` — 각 페이지에 **버전·시행일** 표기, 이전 버전 열람 링크.
- 처리방침에 **처리위탁 목록 표**, **국외 이전 표**, **자동화 처리 개요**, **CPO 연락처**, **권리 행사 방법**, **파기 절차** 포함.

### A-8. 최소 안전조치(코딩 레벨)

- 비밀번호 해시(bcrypt/scrypt/argon2), 세션 httpOnly+Secure+SameSite.
- 전송 구간 TLS, 저장 구간 민감 필드 암호화(기록·문자·말투 요약).
- AI 전송 시 **어떤 데이터 유형을 어느 벤더로 보냈는지 감사 로그**(원문 저장 금지).
- 접근권한 최소화, 관리자 접속기록 보관.

## C. 법률 전문가에게 확인해야 하는 사항

1. **제3자(연인) 개인정보를 이용자가 입력하는 구조**의 적법 근거, 동의 필요성, 약관·고지 문구의 충분성.
2. **대화 내용·대화 스크린샷**의 성격(통신 내용/민감정보) 및 **국외 AI 전송 시 별도 동의 필요 여부**.
3. **사전 질문 "가치관"** 및 자유 서술·캡처에 유입되는 **민감정보의 별도 동의 요부**, 질문 재설계로 회피 가능한지.
4. **AI API 전송의 법적 성격** — 처리위탁으로 구성 가능한지, §28-8①3호(처리방침 공개)로 **국외 이전 동의를 갈음할 수 있는지**, 어떤 데이터까지 갈음 가능한지.
5. **AI 벤더별(OpenAI/Anthropic/Google) 데이터 학습·보관 정책**의 계약상 확인 방법과, 학습 사용 시 "제공"으로의 전환 판단.
6. **자동화된 결정(§37-2)** 적용 여부 — 카드 분류·추천·아이템 제안이 "중대한 영향"에 해당하는지, 처리방침 공개 의무 범위.
7. **만 14세 미만** — 가입 차단으로 충분한지, 연령 확인 수단의 적정성.
8. **커플 관계 정보(특히 동성 커플)** 의 성적 지향(민감정보) 해당성과 취급 방법.
9. **보관기간** 산정(로그 1년/2년, 동의 이력, 탈퇴 후 잔존 항목, 백업 파기)의 적정성.
10. **처리방침·약관 최종본** 및 **국외 이전 공개문**의 법적 충분성.
11. 무료 서비스라도 요구되는 **소비자보호·전자상거래법상 표시의무** 유무(향후 유료화 대비 포함).
12. 개인정보 **영향평가(PIA)** 권고 여부(민감정보·대량 처리·신기술 활용 관점).

## D. 현재 PRD/기능명세서에 추가로 명시해야 하는 개인정보 관련 요구사항

> PRD §10 "개인정보 처리 관련 개발 원칙"은 추가됨. 아래는 **요구사항(R-) 수준으로 추가 권장**하는 항목이다(번호는 예시).

| 신규 R (예시) | 내용 | 등급 |
|---|---|---|
| R-42 약관·동의 관리 | 회원가입 시 필수/선택 동의 항목을 개별 체크로 받고, 항목·버전·시각·IP를 저장한다. 문서 버전 변경 시 재동의를 받는다 | 필수 |
| R-43 연령 확인 | 생년월일로 **만 14세 미만 가입을 차단**한다(또는 법정대리인 동의 절차) | 필수 |
| R-44 정보주체 권리 화면 | 설정에서 내 정보 열람, 기록·카드·말투 프로필·문자 삭제, 커플 연결 해제, 회원 탈퇴를 제공한다. 처리 결과·기한을 안내한다 | 필수 |
| R-45 연인(제3자) 정보 입력 고지 | 사전 질문·기록·캡처 업로드 화면에 제3자 정보·민감정보 관련 고지를 상시 표시하고, 이용자 책임을 약관에 명시한다 | 필수 |
| R-46 커플 연결 상호 동의 | 연결 수락 시 "상대의 기록·분석 대상이 됨(각자의 기록·카드는 비공개)"에 대한 동의를 양쪽에서 받는다 | 필수 |
| R-47 대화 캡처 처리 고지·삭제 증적 | 캡처 업로드 전 목적·국외 전송·즉시 삭제를 고지하고, 분석 성공/실패와 무관하게 원본을 삭제하며 삭제 이벤트를 로그로 남긴다(원문 미포함) | 필수 |
| R-48 AI 전송 데이터 관리 | 외부 AI로 전송되는 데이터 유형·목적·벤더·국외 이전 여부를 매핑·관리하고 내부 감사 로그를 남긴다. 벤더의 학습 미사용·보관정책을 계약으로 확인한다 | 필수 |
| R-49 개인정보 처리방침·국외 이전 공개 페이지 | 처리방침, 처리위탁 목록, 국외 이전 표, 자동화 처리 개요, CPO 정보를 공개하는 페이지를 제공한다(버전·시행일 표기) | 필수 |
| R-50 미연결 사전 질문 응답 파기 | 커플 연결이 일정 기간(예: 30일) 내 성사되지 않으면 사전 질문 응답과 그로부터 생성된 카드를 파기한다 | 권장 |
| R-51 보관기간·파기 정책 | 데이터 유형별 보관기간을 정의하고, 기간 경과·목적 달성 시 지체 없이 파기한다(백업 포함) | 필수(문서+구현) |
| R-52 유출 대응 | 개인정보 유출 감지 시 정보주체 통지 및 규모별 신고(72시간) 절차를 갖춘다 | 필수(운영) |
| R-53 민감정보 유입 최소화 | "가치관" 질문을 종교·정치·성적 지향을 유도하지 않는 형태로 설계하고, AI가 민감 카테고리를 추론·저장하지 않도록 후처리한다 | 필수 `[법률 검토]` |
| R-54 마케팅 수신 동의(선택) | 광고성 정보 수신을 선택 동의로 받고, 철회 수단과 2년 주기 재확인을 제공한다. **야간(21~08시)에는 광고성 정보를 발송하지 않는다**(야간 수신 동의 항목 없음) | 서브 |
| R-55 자동화 처리 고지 | AI 분류·추천의 개요·기준을 처리방침에 공개하고, 이용자가 결과(카드)를 수정·삭제할 수 있게 한다(R-21과 연계) | 필수 |

인증 방식은 **이메일+비밀번호 회원가입 + 이메일 인증으로 확정**되어 있으며(PRD §3.3·§4.1·§7.1, 스펙 R-1·R-2), 소셜 로그인은 도입하지 않는다. 추가 요구사항은 이 전제에서 정의한다.
