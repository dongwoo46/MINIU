# MINIU(미니유) 웹 MVP PRD

기준 입력: `미니미_PRD_v2.pdf`(이 대화에 첨부, repo 밖 — 당시 가제 "미니미"). 참고: `docs/features/miniu/tech.md`.

이 문서는 앱 기준으로 작성된 PRD v.2 초안을 **웹 서비스**로 옮기고, 초안 내용을 그대로 유지하되 이번 프로젝트에서 확정한 사항을 반영한 최종 PRD다. 웹이며 화면은 **모바일 뷰를 기준으로 반응형**으로 대응한다(모바일 우선, 더 넓은 화면도 지원). 초안 대비 바뀐 점은 아래 "초안 대비 변경" 절에 모았다. 네이티브 앱은 이번 범위가 아니며 별도 페이즈(§7)로 다룬다. 문서 전체에서 기록·미니유의 대상은 **"연인"**으로 부른다. **서비스명은 MINIU(미니유)로 확정**했으며(가제 "미니미" 대체), 사용자가 만드는 캐릭터도 "미니유"로 부른다.

## 초안 대비 변경

- 플랫폼: 앱 → **웹 서비스**(모바일 뷰 기준 반응형, 콘텐츠 최대 폭 460px). 네이티브 앱은 후속 페이즈(§7).
- 기능 등급: **필수 / 메인 / 서브 / 버림** 4등급. 메인(기록·AI 프로필 카드·미니유 AI 채팅)을 서브(집·문자·아이템·공유·알림)보다 먼저 배치(§3.1, §4).
- 계정: 소셜 로그인 삭제, **일반 회원가입**만 제공(이름·생년월일·이메일·이메일 인증·약관 동의, 비밀번호 8~16자·숫자와 특수문자 포함).
- 온보딩: **회원가입 → 커플 연결 링크(회원가입 이메일로 공유, 미연결이어도 진행) → 사전 질문 5개(전부 필수) → 홈(미니유 자리 물음표) → (커플 연결 후) 미니유 생성** 순서로 재정의(§2, §4.2~4.4).
- 미니유 생성·수정: **커플 연결 후에만** 가능. 연결 전에는 물음표를 눌러도 연결 안내만 표시된다. "최초 생성 후 잠금"은 삭제(연결 유지 중에는 미니유 집에서 언제든 수정).
- 사전 질문 신설: 사귄 날짜 + 연인의 좋아하는 것·싫어하는 것·성향·습관·가치관. 응답은 초기 프로필 카드와 D-day가 되며, 재연결 시에도 동일하게 적용(R-6).
- 프로필 카테고리: **주의점 → 가치관**으로 변경, **기념일 카테고리 삭제** → 5종(좋아하는 것 / 싫어하는 것 / 가치관 / 습관 / 성향). 선물 힌트 등 5종에 없는 정보는 카드로 만들지 않는다.
- 카드 병합: 규칙 기반 문자열 일치 → **AI가 병합 후보를 판단하고, 병합 전에 항상 사용자에게 "같은 정보로 볼까요?" 확인**(자동 병합 없음)(R-18).
- 기록 삭제: 그 기록이 출처인 프로필 카드도 함께 삭제(R-16).
- AI 분석 재시도: 네트워크 등 일시적 오류로 실패한 경우에만 제공(R-19).
- 커플 연결 해제: 문자·기록·카드·말투·아이템 제안뿐 아니라 **연인 미니유·사전 질문 원본 응답도 삭제**, **30일 유예 후 완전 삭제**하고 사전 안내. 재연결 시 이전 데이터는 복구 없이 온보딩 재진행(R-11).
- 사진 기반 외모 AI 분석: **서비스에서 영구 삭제**.
- 이미지 업로드: 일부 실패 시 성공분을 먼저 반영하고 "N개 실패"를 알린다(R-6, R-26, R-33).
- 문자: 스티커 제외, 대신 **텍스트형 이모지(예: OTL)** 제공. 문자 "저장" = 카드형 이미지 다운로드(R-33, R-35).
- 공유 이미지: **미니유 생성 직후부터** 사용 가능. 대표 문구는 AI 3개 제안 또는 **사용자 직접 입력**(기본 문구 세트 없음)(R-39, R-40).
- 공유 이미지 D-day: 사귄 날짜 기준, 표시는 선택(R-39).
- 기록 본문 최대 길이: **150자**.
- **기록 비공개**: 연인에 대한 기록·프로필 카드·사전 질문 응답·AI 채팅·말투 프로필은 **작성한 본인만 열람**한다. 커플로 연결되어도 연인은 상대가 남긴 기록·카드를 볼 수 없다. 커플 연결은 문자·애정표현·미니유 상호작용을 여는 것이다(§5.2).

## 용어

- **연인**: 사용자가 기록하고 미니유로 만드는 상대. 문서 전체에서 "상대방" 대신 "연인"으로 쓴다.
- **미니유**: 사용자가 연인을 본떠 만든 캐릭터. 외형(헤어스타일·머리색·피부톤·얼굴형·표정)과 이름으로 구성한다.
- **커플 연결**: 두 계정을 1:1로 묶는 상태. 연결되어야 미니유 생성, 기록·프로필·AI 채팅·문자·집 방문을 이용할 수 있다.
- **사전 질문**: 온보딩에서 연인의 사귄 날짜와 5개 항목(좋아하는 것·싫어하는 것·성향·습관·가치관)을 묻는 단계. 모두 필수이며, 응답은 초기 프로필 카드와 D-day가 된다.
- **기록**: 연인에 대해 알게 된 것을 적은 텍스트 항목. 내용(최대 150자)과 선택 날짜로 구성한다.
- **사실 단위**: AI가 기록·사전 질문 응답·문자를 쪼갠 최소 정보 조각. 카드 분류와 병합의 기준이다.
- **프로필 카드**: 사실 단위를 5개 카테고리(좋아하는 것 / 싫어하는 것 / 가치관 / 습관 / 성향) 중 하나로 분류해 만든 카드. 내용과 출처(사전 질문 · 기록 · 문자)를 담는다.
- **말투 프로필**: 대화 캡처에서 AI가 요약한 연인의 말투 정보(분위기·어미·자주 쓰는 표현·이모지·답변 길이·반응 방식). 원문은 저장하지 않고 AI 채팅 말투에만 쓴다.
- **미니유 집**: 홈에서 이동하는 연인 미니유의 공간. 미니유 확인·꾸미기, 아이템 착용·해제, 애정표현을 한다.
- **아이템 / 인벤토리**: 연인의 구체적 취향에서 파생된 착용·휴대형 아이템과 그 보관함(최대 10개).
- **대표 문구**: 공유 이미지에 넣는 한 줄. AI가 프로필 카드를 근거로 3개 제안하거나 사용자가 직접 입력한다.
- **D-day**: 연인과 사귀기 시작한 날. 사전 질문에서 입력받아 저장하고, 공유 이미지에 선택적으로 표시한다.

## 1. 문제와 목표

- 사용자: 연인의 취향·습관·성향·가치관·특별한 날을 기억하고 싶은 10~30대 커플. 바쁜 일정이나 장거리 연애로 자주 만나기 어렵고, 캐릭터 꾸미기·기록·감성적 소통을 좋아하는 사용자.
- 문제: 연인에 대해 알게 된 정보를 그때그때 기억하지 못하고 흩어진 채로 잊는다. 메모 앱은 기록이 재활용되지 않고, 떨어져 있는 시간에는 연결감을 유지할 접점이 없다.
- 목표:
  - 연인에 관한 정보를 부담 없이 기록하고 기억한다.
  - AI가 기록·사전 질문·문자에서 중요한 정보를 사실 단위로 추출해 프로필 카드로 정리한다.
  - 미니유와의 대화, 집 방문, 애정표현으로 떨어져 있는 시간에도 연결감을 만든다.
  - 연인의 취향을 반영한 미니유 아이템과 SNS 공유 이미지를 제공한다.
- 핵심 가치: "연인에 대해 알게 된 정보를 잊지 않고 기록하며, 더 잘 알아가는 경험."
- North Star: 가입 후 7일 내 첫 기록 작성률 / 주간 기록 작성 수 / AI 프로필 카드 생성·수정률 / AI 채팅 사용률. 전체 성공 지표는 §8.

## 2. 핵심 흐름

1. 진입: 이름·생년월일·이메일로 **회원가입**하고 이메일 인증과 약관 동의를 마친다. **커플 연결 링크**를 만들어 연인에게 공유하거나 받은 링크·코드를 입력한다(연결되지 않아도 넘어갈 수 있다). **사전 질문**(사귄 날짜 + 연인이 좋아하는 것·싫어하는 것·성향·습관·가치관 5개, 전부 필수)에 답한다. 홈에 들어가면 연인 미니유 자리에 물음표가 있고, **커플 연결이 완료되면** 눌러서 미니유를 생성한다(연결 전에는 생성 불가).
2. 행동: 홈에서 연인 미니유와 집을 본다. **기록 탭에 연인에 대해 알게 된 것을 적으면 AI가 사실 단위로 나눠 5개 카테고리 프로필 카드로 자동 정리한다**(사전 질문 응답도 초기 카드가 된다). 프로필 탭에서 카테고리별 카드를 조회·수정·삭제하고, 홈에서 연인 미니유를 눌러 **AI와 대화**한다. (서브) 집에 방문해 미니유를 꾸미고 애정표현을 남기며, 문자를 주고받는다.
3. 결과: 연인에 대한 정보가 흩어지지 않고 카드로 축적되어 계속 다시 볼 수 있고, 미니유와 대화하고 집·애정표현으로 떨어져 있어도 연결감을 유지하며, 현재 미니유 씬을 대표 문구·D-day와 함께 공유 이미지로 저장한다.

### 2.1 상세 사용자 흐름

1. 회원가입(이름·생년월일·이메일·비밀번호 8~16자·숫자와 특수문자 포함) → 이메일 인증 → 약관 동의.
2. 커플 연결 링크·일회성 코드를 만들어 회원가입 때 인증한 이메일을 통해 연인에게 공유하거나, 받은 링크·코드를 입력한다. 연결이 성사되지 않아도 온보딩을 계속한다.
3. 사전 질문(사귄 날짜 + 좋아하는 것·싫어하는 것·성향·습관·가치관)에 모든 항목을 입력한다(전부 필수).
4. 홈에 진입한다. 연인 미니유 자리에 물음표가 표시된다.
5. 연인이 링크·코드로 수락하면 커플로 연결된다.
6. 커플 연결 후 물음표를 눌러 프리셋·외형·이름을 설정해 미니유를 생성한다. 연결 전에는 물음표를 눌러도 연결 안내만 표시되고 미니유를 만들 수 없다.
7. (선택) 미니유 생성 단계 또는 이후 채팅 설정에서 대화 캡처를 최대 4장 업로드해 말투를 설정한다. 말투는 이후에도 수정할 수 있다.
8. 홈에서 연인 미니유를 눌러 AI 채팅을 시작한다.
9. 기록 탭에 연인에 대해 새롭게 알게 된 정보를 작성한다.
10. AI가 기록·사전 질문·문자에서 정보를 사실 단위로 추출해 프로필 카드로 자동 분류한다.
11. 프로필 탭에서 카테고리별 정보를 확인하고 수정·삭제한다.
12. (서브) 집에 방문해 애정표현을 남기고 연인 미니유를 꾸민다.
13. (서브) 기록이 누적되면 AI가 취향 기반 아이템을 제안한다. 공유 이미지는 미니유 생성 직후부터 저장할 수 있다.

## 3. 범위

### 3.1 기능 등급

| 등급 | 포함 기능 | 개발·품질 방침 |
|---|---|---|
| 필수기능 (P0) | 일반 회원가입·로그인·라우팅·웹 셸/탭, 온보딩(커플 연결 링크·사전 질문·홈 첫 진입), 미니유 생성, 커플 연결, 공통 기반(연결 해제·에러/빈 상태·로깅·민감 데이터) | MVP 1차에 반드시 포함. 버그 수정·안정화 최우선 |
| 메인기능 (P1) | 기록, AI 프로필 카드 자동 생성, 프로필 카드 관리, 미니유 AI 채팅·말투 | MVP 1차에 포함. 서비스 핵심 가치. 분류·병합 정확도와 채팅 품질을 반복 개선 |
| 서브기능 (P2) | 홈 꾸미기·집 방문·애정표현·미니유 꾸미기 → 문자 → AI 아이템·인벤토리 → 공유 이미지 → 인앱 알림 | 필수+메인 안정화 후 이 순서대로 추가. 시간 부족 시 그룹 단위로 뒤로 미룸 |
| 버릴기능 | 사진 기반 외모 AI 분석 | 서비스에서 제외. 향후에도 만들지 않는다 |

- **MVP 1차 커밋 = 필수기능 + 메인기능.** 서브기능은 각 그룹이 독립적으로 붙었다 빠질 수 있게 설계한다.

### 3.2 포함 (웹 MVP)

- 일반 회원가입·이메일 인증, 모바일 뷰 기준 반응형 웹 셸, 하단 탭 내비게이션(홈 / 기록 / 프로필 / 문자).
- 온보딩: 커플 연결 링크·코드, 사전 질문 5개, 홈 첫 진입.
- 미니유 생성과 기본 커스터마이징(커플 연결 후), 미니유 집에서의 미니유 수정.
- 대화 캡처 기반 말투 설정.
- 초대 링크·일회성 코드 기반 커플 연결과 연결 해제.
- 홈, 미니유 클릭 AI 채팅, 집 방문.
- 텍스트 기반 연인 정보 기록, 기록·사전 질문·문자 기반 AI 프로필 카드 자동 생성, 카테고리별 카드 조회·수정·삭제.
- 문자 작성·답장, 카드형 이미지 저장·공유.
- 애정표현 인터랙션, 취향 기반 아이템 제안과 인벤토리.
- D-day 선택을 포함한 공유 이미지 저장.
- 인앱 알림.

### 3.3 제외 (이번 MVP 밖)

- 소셜 로그인(구글·카카오·애플 등). **일반 회원가입만 제공한다.**
- 사진 기반 외모 AI 분석(§3.1 버릴기능).
- 네이티브 앱과 부속: 네이티브·웹 푸시, 백그라운드 동기화, 앱스토어 배포, 네이티브 공유 시트, 생체 인증, 카메라 직접 촬영.
- 실시간 음성·텍스트 대화(요청 → 처리 → 응답 방식만). 음성 입력·STT 없음.
- 결제·구독·프리미엄 채팅 이용권, 광고.
- PWA·설치형·오프라인 사용. **MVP는 순수 웹 서비스로만 제작한다.**
- 별도 기념일 등록·알림. D-day는 사귄 날짜 하나만 다룬다.
- 계절별 집 테마, 음성 문자, 미니게임, 아이템 컬렉션.
- 문자 스티커, 문자 스레드, 데이터 내보내기.

### 4.7 [메인] AI 프로필 카드 자동 생성

| ID | 요구사항 | 완료 조건 | 등급 |
|---|---|---|---|
| R-17 | 사실 단위 분리와 자동 분류 | AI가 기록·사전 질문 응답·문자를 사실 하나 단위로 분리해 좋아하는 것·싫어하는 것·가치관·습관·성향 중 하나로 분류하고 프로필 카드로 만든다. 분류된 카드는 프로필 탭에 카테고리별로 노출된다 | 메인 |

| R-19 | 분석 실패 복구 | AI 분석이 실패해도 기록·문자·사전 질문 응답은 정상 저장된다. **네트워크 오류·타임아웃 등 일시적 오류로 실패한 경우에만 "다시 분석" 재시도를 제공하고**, 그 외 사유는 재시도 없이 기록 탭에만 남긴다. 실패가 원본 저장이나 다른 기능을 막지 않는다 | 메인 |

| R-23 | 변경 즉시 반영 | 수정·삭제된 카드는 AI 채팅, 아이템 생성, 공유 대표 문구 생성에 즉시 반영된다 | 메인 |

### 4.9 [메인] 미니유 AI 채팅과 말투

| ID | 요구사항 | 완료 조건 | 등급 |
|---|---|---|---|
| R-24 | 미니유 AI 채팅 | 홈에서 연인 미니유를 눌러 AI 채팅을 시작한다. AI는 프로필 카드·기록·문자 정보를 참고해 답변 내용을 생성한다 | 메인 |
| R-25 | 채팅 말투 | AI는 대화 캡처 말투 프로필을 참고해 답변 말투를 생성한다. 말투 프로필이 없으면 서비스 공통 기본 말투를 쓴다. **말투 프로필은 미니유 생성 이후에도 채팅 설정에서 다시 설정·수정할 수 있다.** 이후 작성되는 기록·문자는 말투를 바꾸지 않는다 | 메인 |
| R-26 | 대화 캡처 말투 설정(선택) | 미니유 생성 단계 또는 이후 채팅 설정에서 대화 캡처 이미지를 최대 4장까지 업로드할 수 있다. AI는 연인이 보낸 메시지를 중심으로 말투 분위기·어미·자주 쓰는 표현·이모지·답변 길이·반응 방식을 요약해 말투 프로필로 저장한다. 원본 캡처는 분석 완료 직후 삭제하고 요약만 저장하며, 커플 연결 해제 시 말투 프로필은 자동 삭제된다. 분석 실패 시 기본 말투를 적용한다. 일부 파일 업로드 실패 시 성공한 파일을 먼저 반영하고 "N개 실패"를 알린다 | 메인 |
| R-27 | 채팅 사용량 제한 | AI 채팅은 하루 20회로 제한하고 답변 생성이 끝났을 때만 1회 차감한다. 남은 채팅 횟수와 다음 초기화 시점을 채팅 화면에 표시하며, 한국 시간 기준 매일 자정에 초기화한다 | 메인 |

## 5. 예외와 제약

### 5.1 실패·빈 상태

- AI 프로필 분석이 실패해도 기록·문자·사전 질문 응답은 정상 저장하고, 프로필 카드 생성만 실패로 표시한다. 네트워크 등 일시적 오류인 경우에만 재시도를 제공한다.
- 대화 캡처 분석이 실패하면 기본 미니유 말투를 적용한다.
- 대표 문구 생성이 실패하면 사용자가 직접 입력하게 한다.
- 이미지 업로드 중 일부 파일이 실패하면 성공한 파일을 먼저 반영하고 실패한 개수를 "N개 실패"로 알린다(대화 캡처·문자 첨부 공통).
- 커플 미연결 상태에서 기록·프로필·AI 채팅·문자·집 방문에 진입하면 연결 안내 화면과 링크 재공유 수단만 보여준다. 미니유 생성·수정도 커플 연결 후에만 가능하다.
- 사전 질문 응답만 있어도 프로필 카드로 반영되므로 홈·프로필·AI 채팅이 정상 동작한다. 데이터가 전혀 없는 화면은 빈 상태 문구로 처리한다.
- AI 채팅 응답 생성 실패는 사용 횟수를 차감하지 않는다.
- 네트워크 끊김·요청 실패 시 작성 중이던 기록·문자·카드 수정 내용은 화면에 유지된다.

### 5.2 권한·데이터

- 이메일 인증 완료 전에는 로그인과 기능 이용을 제한하고 인증 메일 재발송 수단을 제공한다.
- 문자·기록·대화 캡처는 민감 개인 데이터다. 전송 구간을 암호화하고, 대화 캡처 원본은 분석 직후 삭제하며 서비스에는 말투 요약만 저장한다.
- 커플 연결 해제 시 문자·기록·프로필 카드·말투 프로필·관계 기반 AI 아이템 제안과 각자의 연인 미니유·사전 질문 원본 응답을 양쪽에서 삭제 처리하고, 30일 유예 후 완전 삭제한다. 유예 기간·삭제 대상·복구 불가를 해제 전에 안내한다.
- 계정 삭제는 즉시 로그아웃 + 30일 유예 후 완전 삭제하며, 유예 중 재로그인 시 취소된다.
- 한 계정은 동시에 한 명의 연인과만 연결한다.
- **기록 공간은 비공개다.** 연인에 대한 기록·프로필 카드·사전 질문 응답·AI 채팅·말투 프로필은 이를 작성·생성한 사용자 계정에만 귀속되며, 커플로 연결되어도 연인에게 공개·전달되지 않는다. 서로 주고받는 것은 문자와 애정표현 알림뿐이고, 연인 미니유·집·아이템은 각자 자기 것을 만들고 꾸민다.
- 미니유는 계정에 종속되며, 사용자가 만든 연인 미니유는 커플 연결이 유지되는 동안 미니유 집에서 언제든 수정할 수 있고, 연결 해제 시 함께 삭제된다.
- 지속 상태는 서버에 저장한다. `localStorage` 등 브라우저 storage는 신뢰 저장소로 쓰지 않는다.

### 5.3 제약

- 사진 기반 외모 AI 분석은 제공하지 않는다. 사용자가 프리셋을 고른 뒤 직접 외형을 설정한다.
- 미니유 생성과 수정은 커플 연결 후에만 가능하다.
- 미니유·아이템 렌더 방식은 §6에서 프로토타입 테스트 후 결정한다.
- 프로필 카드 카테고리는 좋아하는 것 / 싫어하는 것 / 가치관 / 습관 / 성향 5종이다. 기념일 카테고리는 없고, 선물 힌트 등 5종에 없는 정보는 카드로 만들지 않는다.
- 프로필 카드 병합은 AI가 병합 후보를 판단하되, 병합 전에 항상 사용자에게 확인받은 뒤 진행한다(자동 병합 없음). 사용자가 수정한 카드는 AI가 덮어쓰지 않는다. 분류 불가 기록은 카드로 만들지 않는다.
- 상반된 프로필 정보가 들어오면 최신 기록 기반 정보를 우선 후보로 표시한다.
- 말투 프로필은 AI 채팅 말투에만 활용하고, 이후 작성되는 기록·문자는 미니유 말투를 바꾸지 않는다.
- AI 채팅은 하루 20회로 제한하고, 답변 생성 완료 시에만 1회 차감하며, 한국 시간 자정에 초기화한다. 남은 횟수와 초기화 시점을 화면에 표시한다.
- AI 아이템은 추상적 감정이 아닌 특정 사물·취향에 한정하고, 착용·휴대 가능한 형태여야 하며, 사용자 승인 후에만 생성한다. 최대 10개까지 보유한다.
- 문자 답장은 새 문자로 저장하고 스레드로 묶지 않는다. 읽음 여부는 표시하지 않고 안 읽은 문자만 뱃지로 표시한다. 문자 "저장"은 카드형 이미지 다운로드를 뜻한다.
- 공유 이미지는 미니유 생성 직후부터 쓸 수 있다. 기본형에 실제 이름·문자 원문·기록 원문 등 개인정보를 노출하지 않는다. D-day 표시는 선택이다.
- 기록 본문은 최대 150자다.
- 실시간 대화를 만들지 않는다. AI 채팅은 요청 → 처리 → 응답 방식만 지원한다.
- 응답 시간 목표: 기록 저장은 즉시 완료(분류는 비동기), AI 채팅 첫 응답 텍스트는 5초 이내를 목표로 하고 초과 시 로딩 문구로 전환한다.
- 개인정보·민감 데이터 처리 문구(약관, 처리방침, 삭제 정책)는 기획만으로 확정하지 말고 배포 전 검토를 받는다.

## 7. 플랫폼 전략 (웹 MVP → 네이티브 앱)

### 7.1 웹 MVP

- 모바일 우선 반응형. 최소 지원 폭 320px, 디자인 기준 폭 375px, 콘텐츠 최대 폭 460px(그 이상 화면에서는 460px로 제한하고 중앙 정렬 + 배경 여백). 320px에서 가로 스크롤이 생기지 않아야 한다. 하단 탭은 항상 화면 하단 고정.
- 지원 브라우저: 모바일 Safari·Chrome 최신, 데스크톱 Chrome·Safari·Edge 최신 2개 버전.
- 인증: 이메일+비밀번호(8~16자·숫자와 특수문자 포함) + 이메일 인증, httpOnly 세션 쿠키. 소셜 로그인 없음.
- 파일 업로드: 표준 파일 선택(대화 캡처 최대 4장, 문자 이미지 첨부). 카메라 직접 촬영 없음.
- 공유: 이미지 파일 다운로드 + 초대 링크 복사. Web Share API가 있으면 사용한다.
- 알림: 인앱 알림 센터만.
- 애니메이션(애정표현, 미니유 반응): CSS·웹 애니메이션.
- PWA·서비스 워커·오프라인 캐시는 하지 않는다. MVP는 순수 웹 서비스.

### 7.2 네이티브 앱 페이즈 대비

- 화면·상태·도메인 로직을 API 경계 뒤에 두고 웹 뷰와 앱 뷰가 같은 API를 소비하게 설계한다.
- 초대 링크는 앱 유니버설 링크·딥링크로 승격할 수 있도록 경로 구조를 안정적으로 유지한다.
- 세션 쿠키 방식은 앱에서 토큰 저장으로 대체할 수 있게 인증 응답을 분리해 둔다.
- 앱 페이즈로 미룸: 네이티브 푸시, 네이티브 공유 시트, 백그라운드 동기화, 앱스토어 배포, 생체 인증, 카메라 촬영.

## 8. 성공 지표

- 미니유 생성 완료율.
- 사전 질문 완료율.
- 커플 연결 완료율.
- 가입 후 7일 내 첫 기록 작성률.
- 주간 기록 작성 수.
- AI 프로필 카드 생성 및 수정률.
- 주간 문자 발송 수.
- 주간 집 방문 및 애정표현 횟수.
- AI 채팅 일일 사용률 및 제한 도달률.
- 아이템 제안 승인률.
- 공유 이미지 저장·공유율.
- 7일 및 30일 재방문율.

## 9. 개발·릴리스 순서

1. 필수: 회원가입·이메일 인증·로그인·라우팅·웹 셸/탭.
2. 필수: 온보딩(커플 연결 링크·사전 질문·홈 첫 진입) + 커플 연결·해제 + 미니유 생성(연결 후).
3. 필수: 공통 기반(에러/빈 상태, 이벤트 로깅, 민감 데이터 보호).
4. 메인: 기록 + AI 사실 분리·분류·병합(사용자 확인) + 프로필 카드 관리.
5. 메인: 미니유 AI 채팅 + 대화 캡처 말투 설정.
6. 서브: 홈 화면 구성·집 방문·애정표현·미니유 꾸미기.
7. 서브: 문자.
8. 서브: AI 아이템·인벤토리.
9. 서브: 공유 이미지·대표 문구.
10. 서브: 인앱 알림.

- 각 단계는 이전 단계의 완료 조건을 검증한 뒤 시작한다.
- 서브기능은 그룹 단위로 독립 배포·후퇴가 가능하도록 만든다.
- 출시 후 고도화: 계절별 집 테마, 음성 문자, 미니게임, 아이템 컬렉션, 프리미엄 채팅 이용권, 네이티브 앱.

## 10. 개인정보 처리 관련 개발 원칙

- 개인정보 및 대화 내용은 서비스 기능 수행에 필요한 최소한의 범위에서만 수집·처리한다.
- AI 분석을 위해 외부 AI API로 데이터를 전송하는 경우, 전송되는 데이터의 종류와 목적, 보관 여부, 국외 이전 여부를 명확히 관리한다.
- 대화 스크린샷 등 불필요하게 개인정보가 많이 포함될 수 있는 데이터는 가능하면 분석에 필요한 최소 데이터만 처리하고, 원본 보관이 필요하지 않은 경우 분석 완료 후 삭제하는 것을 우선한다.
- 사용자가 자신의 기록 및 개인정보를 삭제할 수 있도록 한다.
- AI가 사용자의 데이터를 모델 학습 등의 목적으로 재사용하는 경우에는 해당 여부와 이용 목적을 명확히 확인하고 필요한 조치를 한다.
- 위 원칙의 구체적 적용(동의·고지·처리방침·국외이전·제3자(연인) 정보 등)은 별도 검토 문서 `docs/features/miniu/개인정보-법적검토.md`를 따르며, 출시 전 법률 전문가의 최종 검토를 받는다.
